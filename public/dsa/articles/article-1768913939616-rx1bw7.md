## Problem Statement

You are given an integer array ***arr***. Your task is to check if there are any two pairs of elements ***(a, b)*** and ***(c, d)*** within the array such that the sum of the elements in each pair is equal, i.e., **a + b = c + d**. Importantly, each number in these pairs must use distinct indices, meaning that a number can participate in only one pair at a time within the given context.

### Example 1

> [!NOTE]
> **INFO**
> **Input:** arr = [3, 4, 7, 1, 2, 9, 8]
> **Output:** true
> **Explanation:** In the given array, we can form two different pairs of numbers—**(3, 8)** and **(4, 7)**.
> Both pairs add up to the same value: **3 + 8 = 11** and **4 + 7 = 11**. Since at least two distinct pairs have equal sums, the output is **true**.

### Example 2

> [!NOTE]
> **INFO**
> **Input:** arr = [1, 5, 9, 12]
> **Output:** false
> **Explanation:** All possible pairs formed from the array have different sums.
> Since no two distinct pairs add up to the same value, the output is **false**.

### Example 3

> [!NOTE]
> **INFO**
> **Input:** arr = [1, 3, 5, 7, 9]
> **Output: **true
> **Explanation:** From the array, we can form the pairs **(1, 9)** and **(3, 7)**. Both pairs have the same sum: **1 + 9 = 10** and **3 + 7 = 10**. Since two different pairs result in an equal sum, the output is **true**.

### Constraints

- 1 ≤ **arr.size()** ≤ 103
- 1 ≤ **arr[i]** ≤ 104

## Real-Life Analogy

Imagine you're a **matchmaker at a dance competition** organizing couples. Each dancer has a skill level (represented by a number), and you want to create balanced pairs where the **combined skill level** of one pair matches another pair.

Think of it like this:

**Scenario:** You have 7 dancers with skill levels: [3, 4, 7, 1, 2, 9, 8]

**Your Goal:** Find two pairs where the total skill is equal

**Matchmaking Process:**

1. **Pair 1:** Dancer with skill 3 + Dancer with skill 8 = **11 total skill**
2. **Pair 2:** Dancer with skill 2 + Dancer with skill 9 = **11 total skill** ✓

**Perfect Match!** Both pairs have equal combined skill levels.

**Important Rule:** Each dancer can only be in ONE pair (can't use the same person twice)

This is exactly what the "Sum Equals to Sum" problem does - it finds whether you can form two pairs from the array where the sums are equal, ensuring each element is used only once!

## Brute-Force Approach

### Intuition

The most straightforward approach is to check **all possible combinations** of four distinct elements and see if any two pairs have equal sums. We use four nested loops to try every possible combination of indices (i, j, k, l) where all are distinct, then check if **arr[i] + arr[j] == arr[k] + arr[l]**.

The key steps are:

1. **Try all combinations** of four distinct indices
2. **Check if first pair sum equals second pair sum**
3. **Return true** immediately when found
4. **Return false** if no such pairs exist

### Algorithm

1. We start by getting the length of the array because it helps us control the iteration range and also lets us check whether the problem is solvable. If the length of the array is **less than 4**, we immediately return **false**, because at least **four different elements** are required to form **two pairs**.
2. Next, we try to examine **all possible ways to select four distinct elements** from the array. To do this systematically, we pick elements in increasing order of their indices.
3. 1. This ensures that:
  2. 1. All selected indices are different.
    2. No combination is repeated.
  3. Every valid group of four elements is checked. So, we choose:
  4. 1. the first element,
    2. the second element after the first,
    3. the third element after the second,
    4. and the fourth element after the third.
4. Once we have a group of **four elements**, we need to check whether they can be split into **two pairs with equal sums**. For any four elements, there are exactly **three valid ways** to form two pairs:
5. 1. First element with second, and third with fourth.
  2. First element with third, and second with fourth.
  3. First element with fourth, and second with third.
6. For each of these pairings, we calculate the sum of both pairs and compare them. If **any pairing produces equal sums**, we immediately return **true**, because the required condition is satisfied and there is no need to check further combinations. This early termination helps avoid unnecessary work.
7. If we finish checking **all possible combinations of four elements** and **none of the pairings have equal sums**, then it means no such pairs exist in the array. Finally, we return **false** as the result.

### C++ Implementation

```cpp
class Solution {
public:
    // Brute Force Approach - Check all combinations
    bool sumEqualsSum(vector<int>& arr) {
        int n = arr.size();

        // Step 1: Need at least 4 elements for two pairs
        if (n < 4) {
            return false;
        }

        // Step 2: Four nested loops for all combinations
        for (int i = 0; i < n - 3; i++) {
            for (int j = i + 1; j < n - 2; j++) {
                for (int k = j + 1; k < n - 1; k++) {
                    for (int l = k + 1; l < n; l++) {

                        // Step 3: Check all three pairing possibilities

                        // Pairing 1: (i, j) and (k, l)
                        if (arr[i] + arr[j] == arr[k] + arr[l]) {
                            return true;
                        }

                        // Pairing 2: (i, k) and (j, l)
                        if (arr[i] + arr[k] == arr[j] + arr[l]) {
                            return true;
                        }

                        // Pairing 3: (i, l) and (j, k)
                        if (arr[i] + arr[l] == arr[j] + arr[k]) {
                            return true;
                        }
                    }
                }
            }
        }

        // Step 5: No equal sum pairs found
        return false;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(**n⁴**)

- (where, '**N'** = length of the array).
- We first check if the array length is less than 4, which takes constant time.
- Then, we use four nested loops to generate all possible combinations of 4 distinct elements from the array.
- The first loop runs `n` times, the second loop runs approximately `n` times for each iteration of the first loop, the third loop runs approximately `n` times for each pair `(i, j)`, and the fourth loop runs approximately `n` times for each triple `(i, j, k)`.
- For each combination, we perform constant-time sum calculations and comparisons.
- So, the total time complexity becomes: **O(n × n × n × n) = O(n⁴)**.

#### Space Complexity: O(1)

- (where, no extra space is used apart from variables).
- We only use a few loop variables and temporary variables to store sums, all of which take constant space.
- No additional data structures are used, and the input array is not modified or copied.
- So, the total auxiliary space complexity is: **O(1)**.

## Optimal Approach

### Intuition

The brute-force method checks every possible combination of four elements, which results in a very high **O(n⁴)** time complexity. This is inefficient and unnecessary.

The key observation is that we do not actually need to select four elements at once.
If **two different pairs of elements have the same sum**, then the condition is already satisfied.

So instead of working with four elements directly, we:

- Focus on **pair sums**
- Store these sums as we traverse the array
- Reuse previously computed information using a **HashMap**

This allows us to reduce the problem to checking whether the same sum appears again with **different indices**, making the solution much faster.

### Algorithm

1. First, get the length of the array. If the size is less than 4, return false immediately because at least four elements are required to form two distinct pairs. Initially we initialize a HashMap to store pair sums and their corresponding indices.

- - Key → sum of a pair
  - Value → indices of the elements that form the pair
- This helps us quickly check whether a sum has appeared before and whether it was formed using different elements.

1. Use two nested loops to generate all possible pairs of elements in the array. The first loop selects the first element, and the second loop selects the next element after it. This will ensures as each pair is considered only once and duplicate pairs are avoided. Hence, all the valid combinations are covered.
2. For each pair, calculate the sum of the two elements. Check if this sum already exists in the HashMap.

- If the sum does not exist, store the sum and the current pair’s indices in the map.
- If the sum does exist, retrieve the previously stored indices and compare them with the current pair’s indices.

1. Further, we check for distinct indices. Ensure that all four indices (from the current pair and the previous pair) are different. This guarantees that the two pairs are formed using four distinct elements. As if all **indices** are **distinct**, **return true** immediately. And if indices overlap, **continue** **searching** because a **valid pair might appear later**.
2. At last we return the final result. After checking all pairs. If no two distinct pairs with equal sums are found, **return false**.

### C++ Implementation

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    // Optimal Approach - Using HashMap
    bool sumEqualsSum(vector<int>& arr) {
        int n = arr.size();

        // Step 1: Need at least 4 elements
        if (n < 4) {
            return false;
        }

        // Step 2: HashMap to store sum -> pair of indices
        unordered_map<int, pair<int, int>> sumMap;

        // Step 3: Generate all pairs
        for (int i = 0; i < n - 1; i++) {
            for (int j = i + 1; j < n; j++) {

                // Step 4a: Calculate current pair sum
                int currentSum = arr[i] + arr[j];

                // Step 4b: Check if sum exists
                if (sumMap.find(currentSum) != sumMap.end()) {

                    // Retrieve previous pair
                    auto [p, q] = sumMap[currentSum];

                    // Check if all indices are distinct
                    if (i != p && i != q && j != p && j != q) {
                        // Found two pairs with equal sums and distinct indices
                        return true;
                    }
                }

                // Step 4c: Store current pair
                sumMap[currentSum] = {i, j};
            }
        }

        // Step 5: No matching pairs found
        return false;
    }
};
```

class Solution {
    // Optimal Approach - Using HashMap
    public boolean sumEqualsSum(int[] arr) {
        int n = arr.length;
        
        // Step 1: Need at least 4 elements
        if (n < 4) {
            return false;
        }

        Map<Integer, int[]> sumMap = new HashMap<>();
        
        // Step 3: Generate all pairs
        for (int i = 0; i < n - 1; i++) {
            for (int j = i + 1; j < n; j++) {
                // Step 4a: Calculate current pair sum
                int currentSum = arr[i] + arr[j];
                
                // Step 4b: Check if sum exists
                if (sumMap.containsKey(currentSum)) {
                    // Retrieve previous pair
                    int[] prevPair = sumMap.get(currentSum);
                    int p = prevPair[0];
                    int q = prevPair[1];
                    
                    // Check if all indices are distinct
                    if (i != p && i != q && j != p && j != q) {
                        // Found two pairs with equal sums and distinct indices
                        return true;
                    }
                }
                
                // Step 4c: Store current pair
                sumMap.put(currentSum, new int[]{i, j});
            }
        }
        
        // Step 5: No matching pairs found
        return false;
    }
}

### Complexity Analysis

#### Time Complexity: O(n²)

- Nested loops generate all pairs **(i, j)** in the array: total pairs ≈ **n × (n-1)/2 = O(n²).**
- Each pair requires constant time for sum calculation, HashMap lookup, and insertion.
- **Overall:** O(n²)
- **Best case:** O(1) if early termination occurs
- **Worst/Average case:** O(n²)

### **Space Complexity: **O(n²)

- HashMap stores sums as keys and index pairs as values.
- Worst case: all pairs have unique sums → O(n²) entries.
- Temporary variables use O(1) space.
- **Overall auxiliary space:** O(n²).
