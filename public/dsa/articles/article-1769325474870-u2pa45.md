## Problem Statement

Given an array consisting of both positive and negative integers, your task is to find the length of the largest subarray which has a sum that equals zero. A subarray is a contiguous portion of the array, meaning the elements are consecutive.

### Example 1

> [!NOTE]
> **INFO**
> **Input:** n = 8, arr = [15, -2, 2, -8, 1, 7, 10, 23]
> **Output:** 5
> **Explanation:** We use prefix sum to track the cumulative sum of elements. When the same prefix sum appears again, the elements between those two indices form a subarray with sum 0. In this array, the prefix sum **15** repeats at indices 0 and 5, so the subarray **[-2, 2, -8, 1, 7]** has sum 0 and length **5**, which is the maximum.

### Example 2

> [!NOTE]
> **INFO**
> **Input:** n = 5, arr = [1, 2, -2, 4, -4]
> **Output:** 4
> **Explanation:** We calculate the prefix sum of the array. The prefix sum becomes **0** at the last index, which means the subarray from the start to that index has sum 0. Hence, the subarray **[1, 2, -2,** 4, -4] has sum 0 and the maximum length is **5**.

### Example 3

> [!NOTE]
> **INFO**
> **Input:** n = 3, arr = [1, -1, 3]
> **Output: **2
> **Explanation:** We track the prefix sum while traversing the array. The prefix sum becomes **0** at index 1, which means the subarray from index 0 to 1 has sum 0. Therefore, the subarray **[1, -1]** has sum 0 and the maximum length is **2**.

### Constraints

- 1 <= **n** <= 105
- -1000 <= arr[i] <= 1000, **for each valid i**

## Real-Life Analogy

Imagine you are a **financial analyst** tracking your company's daily profit and loss. Each day, you either make money (positive) or lose money (negative). You want to find the **longest period where your net profit/loss was exactly zero** - meaning you broke even.

Think of it like this:

**Daily P&L Record:** [+1000, -500, -500, +200, -200]

**Now, do your analysis  Analysis:**

- Day 1: +1000 (profit)
- Day 2-3: -500, -500 (total loss of 1000)
- **Period Day 1 to Day 3:** +1000 - 500 - 500 = **0** (broke even!) → 3 days
- Day 4-5: +200, -200
- **Period Day 4 to Day 5:** +200 - 200 = **0** (broke even!) → 2 days

**Longest break-even period:** 3 days (Day 1 to Day 3)

This is exactly what the problem does it finds the**longest contiguous period** (subarray) where the total sum equals zero!

## Brute-Force Approach

### Intuition

The most straightforward approach is to **check every possible subarray** and **calculate** its sum. If the sum equals zero, we record its length. Among all such zero-sum subarrays, we **return** the **maximum length**. To achieve this, we first generate all possible subarrays using two pointers (start and end). For each subarray, we calculate its sum and check whether it equals zero. While doing this, we continuously track the maximum length found. Finally, we return the maximum length.

### Algorithm

1. First, initialize **maxLength** to **0**. This variable will store the length of the longest zero-sum subarray found so far. We start with **0** because initially no such subarray has been discovered.**maxLength = 0**.
2. Next, obtain the length of the array, **n**. This value will be used as the boundary for our loops while generating all possible subarrays.
3. - To examine every contiguous part of the array, we use **two nested loops**:
  - The **outer loop** runs from **i = 0** to **n - 1**.
This loop represents the **starting index** of each subarray.
  - The **inner loop** runs from **j = i** to **n - 1**.
This loop represents the **ending index** of each subarray.
For every starting index **i**, we try all possible ending positions **j**.
4. For each subarray defined by indices **i** to **j**, we calculate its sum because we need to check whether that subarray has a total sum of zero. 
**To compute the sum:**
5. - Initialize **sum = 0.**
  - Run another loop from **k = i **to **j.**
  - Add each element to the sum using **sum += arr[k].**
  - This gives us the total sum of the subarray **arr[i...j]**.
6. After calculating the sum, we check whether it equals zero, since this is the required condition. If **sum == 0**:
7. - Calculate the current subarray length using
**currentLength = j - i + 1**
  - Update the maximum length by comparing it with the existing value:
**maxLength = Math.max(maxLength, currentLength)**
8. This step ensures that we always keep track of the **longest zero-sum subarray encountered so far**.
9. Finally, after all possible subarrays have been checked, return **maxLength**. This value represents the length of the longest subarray with sum zero, or **0** if no such subarray exists.

### C++ Implementation

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    // Brute Force Approach - Check all subarrays
    int maxLen(vector<int>& arr) {
        int n = arr.size();
        int maxLength = 0;

        // Step 1 & 2: Try all possible subarrays
        for (int i = 0; i < n; i++) {
            int sum = 0;

            for (int j = i; j < n; j++) {
                // Step 3: Calculate sum of subarray [i...j]
                sum += arr[j];

                // Step 4: Check if sum equals zero
                if (sum == 0) {
                    // Step 5: Update maximum length
                    int currentLength = j - i + 1;
                    maxLength = max(maxLength, currentLength);
                }
            }
        }

        // Step 6: Return result
        return maxLength;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(**n****2**)

- Two nested loops are used to generate all possible subarrays.
- The outer loop selects the starting index of a subarray.
- The inner loop selects the ending index for each starting position.
- A running sum is maintained, so adding each new element takes **O(1)** time.
- The total number of subarrays checked is **n × (n + 1) / 2**, which is approximately **O(n²)**.
- Using a running sum optimizes the solution from **O(n³)** to **O(n²)**.

#### Space Complexity: O(1)

- The algorithm uses only a few variables to store values such as the current sum, maximum length, loop counters, and array size.
- No extra data structures like arrays, lists, or hash maps are used, and there is no recursion.
- Because the amount of extra memory used does not depend on the size of the input, the space complexity remains **O(1)**.

## Optimal Approach

### Intuition

The brute-force approach checks all **O(n²)** subarrays, which is inefficient. This can be optimized using the concept of **prefix sums**. While traversing the array, we maintain a running sum. If the same prefix sum appears again at a later index, it means the elements between those two indices form a subarray with sum **0**. This is because when **prefixSum[j] = prefixSum[i]**, the sum from index **i + 1** to **j** becomes zero.

A **HashMap** is used to store each prefix sum along with its first occurrence index. Whenever a prefix sum repeats, we calculate the length of the zero-sum subarray and update the maximum length. This approach efficiently finds the longest zero-sum subarray in **O(n) time**.

### Algorithm

1. Firstly we** initialise required variables** to keep track of the longest zero-sum subarray and the running sum. Then we set **maxLength = 0** to store the maximum length found so far. Set **prefixSum = 0** to maintain the cumulative sum while traversing the array. Next, we create a **HashMap** to store each prefixSum along with the **first index** where it appears.
2. **Now, we handle subarrays starting from index 0** by inserting an initial entry in the HashMap. So, by this we store **prefixSum = 0** at index -1 using map.put(0, -1). This ensures that if the prefix sum becomes 0 at any** index i**, the subarray from **index 0** to** i** is correctly counted.
3. **Next, we traverse the array from index 0 to n − 1** to compute prefix sums and detect zero-sum subarrays.** For each index i:**
4. - Update the running prefix sum by adding the current element: **prefixSum += arr[I].**
5. **After updating the prefix we check whether this prefix sum already exists in the HashMap**:
**If it exists:**
6. - Retrieve the previous index where this prefix sum occurred.
  - The subarray from previousIndex + 1 to i has a sum of zero.
  - Calculate its length as i - previousIndex.
  - Update maxLength using maxLength = Math.max(maxLength, i - previousIndex).

**If it does not exist:**

1. - Store the current prefix sum with index i in the HashMap.
  - Only the **first occurrence** is stored to ensure the longest possible subarray is captured.

**6.****After completing the traversal**, we return maxLength, which represents the length of the longest zero-sum subarray found. If no such subarray exists, the value remains **0**.

### C++ Implementation

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    // Optimal Approach - Using HashMap and Prefix Sum
    int maxLen(vector<int>& arr) {
        int n = arr.size();
        int maxLength = 0;
        int prefixSum = 0;

        // HashMap to store: prefixSum -> first index where this sum occurred
        unordered_map<int, int> map;

        // Step 1: Initialize - handle subarrays starting from index 0
        map[0] = -1;

        // Step 2: Traverse the array
        for (int i = 0; i < n; i++) {

            // Step 3: Update prefix sum
            prefixSum += arr[i];

            // Step 4: Check if this prefix sum has been seen before
            if (map.find(prefixSum) != map.end()) {

                // Found a zero-sum subarray
                int prevIndex = map[prefixSum];
                int currentLength = i - prevIndex;

                maxLength = max(maxLength, currentLength);
            }
            else {
                // Step 5: Store first occurrence of this prefix sum
                map[prefixSum] = i;
            }
        }

        // Step 6: Return result
        return maxLength;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(n)

- The array is traversed **only once**.
- Initial setup (variables and map entry) takes **constant time**.
- For each element:  - Prefix sum is updated.
  - Map lookup, retrieval, and insertion are performed.
  - Subarray length is calculated if needed.
- All these operations take **O(1)** time per element.
- Since this happens for `n` elements, total time is **O(n)**.
- Best, worst, and average cases are all **O(n)** because the full array must be scanned.

### **Space Complexity: **O(n)

- A map is used to store prefix sums and their first occurrence indices.
- In the worst case, all prefix sums are unique, so the map stores up to **n + 1** entries.
- Other variables use only **constant space**.
- Therefore, total auxiliary space is **O(n)**.
