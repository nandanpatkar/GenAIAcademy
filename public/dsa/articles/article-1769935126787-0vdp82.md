## Problem Statement

Given an integer matrix **grid** with dimensions ***m x n***, your task is to find the largest three distinct rhombus sums. A **rhombus sum** is defined by the sum of the cells that form the perimeter of a rhombus shape within the grid, where the rhombus is essentially a square rotated by 45 degrees. It can also include a single cell (representing a rhombus of area 0).

To solve this problem, explore each cell in the matrix as a potential center of a rhombus. From each center, calculate possible rhombus sums by increasing the size from 0 cells (only the center) to the possible size where the entirety of the rhombus stays within the grid boundaries.

After calculating all possible rhombus sums, identify and return the top three distinct sums sorted in descending order. If there are fewer than three distinct sums, return all unique sums.

## Brute-Force Approach

### Intuition

The brute-force approach is to treat every cell in the grid as a potential center of a rhombus and, for each center, expand outward to all possible rhombus sizes allowed by the grid boundaries. For every valid size, we compute the sum of only the **perimeter cells** that form the rhombus shape and store these sums in a set to automatically ensure distinct values. The maximum rhombus size is naturally constrained by how far we can move diagonally without going out of bounds, and careful traversal of the border is required to avoid counting inner cells. After evaluating all centers and sizes, we sort the collected distinct sums in descending order and return the top three values.

### Algorithm

1. **Initialize a set to store rhombus sums** because the problem asks for *distinct* values, and a set automatically prevents duplicate sums from being stored.
2. **Iterate over every cell in the grid as a potential rhombus center** since any cell can form a valid rhombus of size 0 (a single cell), and larger rhombuses may also be centered there.
3. **For each center, determine all valid rhombus sizes** starting from size 0. The maximum possible size is constrained by the grid boundaries, so we only consider sizes that keep the rhombus completely inside the grid.
4. **Compute the rhombus sum for each valid size** by traversing only the *perimeter* of the rhombus, as interior cells do not contribute to the sum. For size 0, the sum is simply the value of the center cell. For larger sizes, the sum is obtained by walking along the four diagonal edges of the rhombus and adding each border cell exactly once.
5. **Add each computed sum to the set** to ensure that only unique rhombus sums are collected across all centers and sizes.
6. **Sort the collected distinct sums in descending order** because we need to identify the largest values.
7. **Return the top three sums (or fewer if fewer than three exist)** since the final result requires only the three largest distinct rhombus sums.

```cpp
class Solution {

public:

    vector<int> getBiggestThree(
        vector<vector<int>>& grid) {

        int m = grid.size();
        int n = grid[0].size();

        // Step 1: Store distinct sums
        set<int> rhombusSums;

        // Step 2: Try each cell as center
        for (int r = 0; r < m; r++) {

            for (int c = 0; c < n; c++) {

                // Step 3: Maximum rhombus size
                int maxSize = min({
                    r,
                    m - 1 - r,
                    c,
                    n - 1 - c
                });

                // Try all sizes
                for (int size = 0;
                     size <= maxSize;
                     size++) {

                    int sum =
                        calculateRhombusSum(
                            grid,
                            r,
                            c,
                            size
                        );

                    rhombusSums.insert(sum);
                }
            }
        }

        // Step 6: Convert to descending order
        vector<int> result;

        for (auto it = rhombusSums.rbegin();
             it != rhombusSums.rend()
             && result.size() < 3;
             ++it) {

            result.push_back(*it);
        }

        // Step 7: Return top 3
        return result;
    }

    // Helper function
    int calculateRhombusSum(
        vector<vector<int>>& grid,
        int r,
        int c,
        int size) {

        // Size 0
        if (size == 0) {
            return grid[r][c];
        }

        int sum = 0;

        // Top-right edge
        for (int i = 0; i <= size; i++) {

            sum += grid[
                r - size + i
            ][
                c + i
            ];
        }

        // Bottom-right edge
        for (int i = 1; i <= size; i++) {

            sum += grid[
                r + i
            ][
                c + size - i
            ];
        }

        // Bottom-left edge
        for (int i = 1; i <= size; i++) {

            sum += grid[
                r + size - i
            ][
                c - i
            ];
        }

        // Top-left edge
        for (int i = 1; i < size; i++) {

            sum += grid[
                r - i
            ][
                c - size + i
            ];
        }

        return sum;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(m × n × min(m, n)² + k log k)
(where **m** = number of **rows, n** = number of **columns, k** = number of **distinct rhombus sums**).

- Iterate over all cells: **O(m × n)**
- For each cell, try all rhombus sizes (max size = min(m, n))
- For each rhombus, calculate perimeter (O(size)) → **O(m × n × min(m, n)²)**
- Sort distinct sums: **O(k log k)**
- Overall: **O(m × n × min(m, n)² + k log k) ≈ O(m × n × min(m, n)²)**

#### Space Complexity: O(k)

- HashSet for distinct sums: **O(k)**
- List for sorting sums: **O(k)**
- Constant extra variables: **O(1)**

## Optimal Approach

### Intuition

- The brute-force approach computes every possible rhombus perimeter sum, keeps only distinct values, and sorts them to find the top three. A tempting optimization is to maintain a min-heap of size 3 while processing, so only the three largest sums are ever held in memory, with the smallest of the three dropped whenever a larger sum appears. In practice, though, this optimization buys very little: the *number of distinct sums* is already bounded by the grid size (at most **m × n × min(m, n)**, though duplicates typically shrink this considerably), so the final sort is cheap regardless. The dominant cost in both approaches is the same, computing every rhombus perimeter sum for every center and size  and that part can't be avoided, since there's no shortcut to know a rhombus's sum without visiting its perimeter cells.

### Algorithm

1. Firstly, we Initialize an empty min-heap (max size 3) to hold the current top three **distinct** sums, plus a small hash set to track which values are already in the heap (so we don't push duplicates).
2. Iterate over every cell **(r, c)** as a potential rhombus center.
3. For each center, compute **maxSize = min(r, m-1-r, c, n-1-c)**.
4. For every size from **0** to **maxSize**, compute the rhombus perimeter sum (same traversal as brute-force, size 0 is just the center,  size > 0 walks the four diagonal edges).
5. If this sum is already tracked in the heap, skip it (no duplicates allowed).
6. Otherwise:  1. If the heap has fewer than 3 elements, push the sum and add it to the tracking set.
  2. Else, if the sum is greater than the heap's minimum (`heap[0]`), pop the minimum out (removing it from the tracking set too) and push the new sum in.
  3. Else, discard the sum — it's not large enough to make the top 3.
7. After processing every center and size, the heap contains exactly the top three distinct sums (or fewer, if fewer than three distinct sums exist). Extract them and sort in descending order for the final result.

```cpp
#include <vector>
#include <queue>
#include <unordered_set>
#include <algorithm>

using namespace std;

class Solution {
public:
    vector<int> getBiggestThree(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        // Min-heap storing at most the 3 largest distinct sums
        priority_queue<int, vector<int>, greater<int>> heap;
        unordered_set<int> inHeap;

        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                int maxSize = min(min(r, m - 1 - r), min(c, n - 1 - c));

                for (int size = 0; size <= maxSize; size++) {
                    int sum = calculateRhombusSum(grid, r, c, size);
                    offerCandidate(heap, inHeap, sum);
                }
            }
        }

        vector<int> result;
        while (!heap.empty()) {
            result.push_back(heap.top());
            heap.pop();
        }

        reverse(result.begin(), result.end());
        return result;
    }

private:
    void offerCandidate(priority_queue<int, vector<int>, greater<int>>& heap,
                        unordered_set<int>& inHeap,
                        int sum) {
        if (inHeap.count(sum))
            return;

        if (heap.size() < 3) {
            heap.push(sum);
            inHeap.insert(sum);
        }
        else if (sum > heap.top()) {
            int removed = heap.top();
            heap.pop();
            inHeap.erase(removed);

            heap.push(sum);
            inHeap.insert(sum);
        }
    }

    int calculateRhombusSum(vector<vector<int>>& grid, int r, int c, int size) {
        if (size == 0)
            return grid[r][c];

        int sum = 0;

        // Top-right edge
        for (int i = 0; i <= size; i++)
            sum += grid[r - size + i][c + i];

        // Bottom-right edge
        for (int i = 1; i <= size; i++)

        // Bottom-left edge
        for (int i = 1; i <= size; i++)
            sum += grid[r + size - i][c - i];

        // Top-left edge
        for (int i = 1; i < size; i++)
```

```java
import java.util.*;

class Solution {
    public int[] getBiggestThree(int[][] grid) {
        int m = grid.length;
        int n = grid[0].length;

        // Min-heap holding at most the 3 largest distinct sums seen so far
        PriorityQueue<Integer> topThree = new PriorityQueue<>();
        // Tracks which sums are currently in the heap, to avoid duplicates
        Set<Integer> inHeap = new HashSet<>();

        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                int maxSize = Math.min(Math.min(r, m - 1 - r),
                                        Math.min(c, n - 1 - c));

                for (int size = 0; size <= maxSize; size++) {
                    int sum = calculateRhombusSum(grid, r, c, size);
                    offerCandidate(topThree, inHeap, sum);
                }
            }
        }

        // Extract and sort the final top-3 (or fewer) in descending order
        int resultSize = topThree.size();
        int[] result = new int[resultSize];
        for (int i = resultSize - 1; i >= 0; i--) {
            result[i] = topThree.poll();
        }

        return result;
    }

    // Push a candidate sum into the top-3 min-heap if it qualifies
    private void offerCandidate(PriorityQueue<Integer> heap, Set<Integer> inHeap, int sum) {
        if (inHeap.contains(sum)) {
            return; // already tracked, skip duplicate
        }
        if (heap.size() < 3) {
            heap.offer(sum);
            inHeap.add(sum);
        } else if (sum > heap.peek()) {
            int removed = heap.poll();
            inHeap.remove(removed);
            heap.offer(sum);
            inHeap.add(sum);
        }
        // else: sum is too small to make the top 3, discard it
    }

    // Helper: Calculate sum of a rhombus's perimeter
    private int calculateRhombusSum(int[][] grid, int r, int c, int size) {
        if (size == 0) {
            return grid[r][c];
        }

        int sum = 0;

        // Top-right edge
        for (int i = 0; i <= size; i++) {
            sum += grid[r - size + i][c + i];
        }

        // Bottom-right edge
        for (int i = 1; i <= size; i++) {
            sum += grid[r + i][c + size - i];

        }

        // Top-left edge
        for (int i = 1; i < size; i++) {
            sum += grid[r - i][c - size + i];
        }

        return sum;
    }
}
```

```python
import heapq

class Solution:
    def getBiggestThree(self, grid):
        m, n = len(grid), len(grid[0])

        # Min-heap storing at most the 3 largest distinct sums
        heap = []
        in_heap = set()

        for r in range(m):
            for c in range(n):
                max_size = min(r, m - 1 - r, c, n - 1 - c)

                for size in range(max_size + 1):
                    rhombus_sum = self.calculateRhombusSum(grid, r, c, size)
                    self.offerCandidate(heap, in_heap, rhombus_sum)

        result = []
        while heap:
            result.append(heapq.heappop(heap))

        return result[::-1]

    def offerCandidate(self, heap, in_heap, value):
        if value in in_heap:
            return

        if len(heap) < 3:
            heapq.heappush(heap, value)
            in_heap.add(value)
        elif value > heap[0]:
            removed = heapq.heappop(heap)
            in_heap.remove(removed)
            heapq.heappush(heap, value)
            in_heap.add(value)

    def calculateRhombusSum(self, grid, r, c, size):
        if size == 0:
            return grid[r][c]

        total = 0

        # Top-right edge
        for i in range(size + 1):
            total += grid[r - size + i][c + i]

        # Bottom-right edge
        for i in range(1, size + 1):
            total += grid[r + i][c + size - i]

        # Bottom-left edge
        for i in range(1, size + 1):
            total += grid[r + size - i][c - i]

        # Top-left edge
        for i in range(1, size):
            total += grid[r - i][c - size + i]

        return total
```

### Complexity Analysis

#### Time Complexity:  **O(m × n × min(m, n)² × log 3) ≈ O(m × n × min(m, n)²)**

- Iterating over all cells and sizes still costs **O(m × n × min(m, n)²)**, same as brute-force — this part is unavoidable since every rhombus sum requires walking its perimeter.
- Each heap operation (push/pop, size capped at 3) is **O(log 3)**, effectively constant.
- No final **O(k log k)** sort over all distinct sums — we only ever sort 3 elements at the end.

#### Space Complexity: O(1)

- The heap and the tracking set never hold more than 3 elements each, regardless of grid size.
- This is the real win over brute-force: space drops from** O(k)** (where **k** can be as large as **m × n × min(m, n)**) down to a small constant.
