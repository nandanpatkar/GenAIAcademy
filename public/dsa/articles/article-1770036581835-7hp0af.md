## Problem Statement

You are given an array of integers ***stones*** where ***stones[i]*** is the weight of the ***i***-th stone.

On each turn, we select the two heaviest stones and smash them together. Suppose the two heaviest stones have weights ***x*** and ***y*** with ***x <= y***.

The result of this smash is as follows:

- If ***x == y***, both stones are completely destroyed.
- If ***x != y***, the stone with weight ***x*** is completely destroyed, and the stone with weight ***y*** has its new weight become ***y - x***.

The new stone (if any) is then added back to the collection.

This process continues until there is at most one stone left. Your task is to return the weight of the last remaining stone. If no stones are left, return 0.

### Example 1

> [!NOTE]
> **INFO**
> **Input:** stones = [2,7,4,1,8,1]
> **Output:** 1
> **Explanation:** We repeatedly smash the **two heaviest stones** until at most one remains:
> 
> 1. Heaviest stones 8 and 7 → smash → 8−7=1 → new collection: [2,4,1,1,1]
> 2. Heaviest stones 4 and 2 → smash → 4−2=2 → new collection: [1,1,1,2]
> 3. Heaviest stones 2 and 1 → smash → 2−1=1 → new collection: [1,1,1]
> 4. Heaviest stones 1 and 1 → smash → 1−1=0 → both destroyed → new collection: [1]
> 5. Only one stone remains → **result = 1**

### Example 2

> [!NOTE]
> **INFO**
> **Input: **stones = [15, 7, 19, 1, 12, 18, 11, 20]
> **Output: **1
> **Explanation:** We are given an array of stone weights. 
> 
> At each step, we **select the two heaviest stones**, smash them together, and:
> 
> - If both stones have the same weight, both are destroyed.
> - If they have different weights, the remaining stone with weight equal to their difference is added back.
> 
> This process continues until **at most one stone remains**.

### Example 3

> [!NOTE]
> **INFO**
> **Input:** stones = [4, 14, 7, 11, 15, 16, 6, 2, 12, 7, 7, 12]
> **Output: **1
> **Explanation:** We repeatedly pick the **two heaviest stones** and smash them:
> 
> 1. Select the two largest stones → smash → if the difference is non-zero, add it back.
> 2. Repeat this process until at most one stone remains.
> 
> For this collection, following this process results in **the last remaining stone = 1**.

### Constraints

- 1** <= stones.length <= **30
- 1** <= stones[i] <= **1000

## Real-Life Analogy

Imagine you are playing a game where you have a collection of rocks of different weights. The rule is simple: you must repeatedly pick the two heaviest rocks and smash them together. When two rocks collide:

- If they are the same weight, both shatter completely and disappear
- If one is heavier, the lighter one is destroyed, and the heavier one loses weight equal to the lighter rock

You keep playing until you either have one rock left or no rocks at all. This is like a tournament elimination where the strongest contestants keep competing, but instead of one winner, the "winner" might be smaller than when they started due to the battles they have fought.

## Brute-Force Approach

### Intuition

The most straightforward way to solve this problem is to simulate the exact process described: repeatedly find the two heaviest stones, smash them together, handle the result, and continue until we have at most one stone left.

In the brute-force approach, we maintain the list of stones and for each turn:

1. Sort the entire array to find the two heaviest stones
2. Remove these two stones from the array
3. Calculate the result of smashing them
4. If a stone remains after smashing, add it back to the array
5. Repeat until only one or zero stones remain

This approach is simple to understand and implement, but it's inefficient because we are sorting the entire array on every turn, which becomes costly as the number of operations increases.

### Algorithm

1. Firstly, we **check** the **base case**, if there is only one stone, **we return its weight** immediately because no smashing is needed.
2. Then, we **convert the array of stones** into a list for easier manipulation, as it allows convenient addition and removal of elements.
3. Next, we **repeat** the process while there are at least** two stones**, we **sort** the list in **descending** **order** to bring the heaviest stones to the front, remove the two heaviest stones, and calculate the difference between them, because smashing the** largest stones** first minimizes the remaining weight. If the difference is greater than 0, we **add the resulting stone back** to the list so it can participate in future smashes.
4. Finally, when **less than two stones remain**, we **return** the **weight of the last stone** if it exists, or **0** if the list is **empty**, because this represents the final remaining weight after all possible smashes.

>

### Code

### C++ Implementation

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int lastStoneWeight(vector<int>& stones) {
        // Keep smashing until at most one stone remains
        while (stones.size() > 1) {
            // Sort in descending order
            sort(stones.begin(), stones.end(), greater<int>());

            // Get two heaviest stones
            int heaviest = stones[0];
            int secondHeaviest = stones[1];

            // Remove the two heaviest stones
            stones.erase(stones.begin());
            stones.erase(stones.begin());

            // Calculate remaining weight after smash
            int remaining = heaviest - secondHeaviest;

            // If there's a remaining stone, add it back
            if (remaining > 0) {
                stones.push_back(remaining);
            }
        }

        // Return the last stone weight, or 0 if none remain
        return stones.empty() ? 0 : stones[0];
    }
};
```

### Python Implementation

```python
class Solution:
    def lastStoneWeight(self, stones):
        # Convert array to list
        stone_list = list(stones)

        # Keep smashing until at most one stone remains
        while len(stone_list) > 1:
            # Sort in descending order
            stone_list.sort(reverse=True)

            # Get two heaviest stones
            heaviest = stone_list.pop(0)
            second_heaviest = stone_list.pop(0)

            # Calculate remaining weight after smash
            remaining = heaviest - second_heaviest

            # If there's a remaining stone, add it back
            if remaining > 0:
                stone_list.append(remaining)

        # Return last stone weight, or 0 if none remain
        return stone_list[0] if stone_list else 0
```

### Complexity Analysis

#### Time Complexity:  O(n² log n)

- In the worst case, we perform **n-1** smashing operations as each operation reduces the number of stones by at least 1.
- Each operation requires sorting the list is **O(n log n)**.
- Total: O(n × n log n) = **O(n² log n)**.

#### Space Complexity: O(n)

- We use a list to **store** the stones is **O(n)**.
- **Sorting** requires additional space which is **O(log n)** for typical implementations.
- So overall space complexity is **O(n)**.

## Optimal Approach

### Intuition

The main thing, is that we always need to access the two heaviest stones. Instead of sorting the entire array every time, we can use a **max-heap** (priority queue) to efficiently maintain the stones in sorted order.

A max-heap allows us to:

- Extract the maximum element in O(log n) time
- Insert a new element in O(log n) time
- Automatically maintain the heap property

By using a max-heap, we can eliminate the need for repeated sorting. We simply:

1. Extract the two heaviest stones (two poll operations)
2. Calculate the result
3. If a stone remains, insert it back (one offer operation)

This reduces the time complexity significantly because heap operations are much faster than sorting the entire array repeatedly.

### Algorithm

1. Firstly, we **initialize **a** max-heap** and **insert all stone weights** into it because a **max-heap** allows us to efficiently access the heaviest stones at each step.
2. Then, we **repeat** the process while there are at **least two stones** in the heap, we **extract** the **heaviest** **stone** and then the **second heaviest stone**, and **calculate** the **difference** between them, because smashing the **two largest stones first ensures** correct simulation of the problem rules. If the difference is **greater than 0**, we **insert** the resulting stone back into the heap so it can participate in future smashes.
3. Finally, when **less than two stones remain**, we **return** **0** if the heap is empty, or the weight of the remaining stone if one stone remains, because this **represents the final remaining stone weight** after all possible collisions.

### Code

### C++ Implementation

```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    int lastStoneWeight(vector<int>& stones) {
        // Step 1: Initialize max-heap
        priority_queue<int> maxHeap;

        // Add all stones to the heap
        for (int stone : stones) {
            maxHeap.push(stone);
        }

        // Step 2: Keep smashing until at most one stone remains
        while (maxHeap.size() > 1) {
            // Extract two heaviest stones
            int first = maxHeap.top();
            maxHeap.pop();

            int second = maxHeap.top();
            maxHeap.pop();

            // Calculate remaining weight
            int remaining = first - second;

            // If there's a remaining stone, add it back
            if (remaining > 0) {
                maxHeap.push(remaining);
            }
        }

        // Step 3: Return result
        return maxHeap.empty() ? 0 : maxHeap.top();
    }
};
```

### Java Implementation

```java
import java.util.*;

class Solution {
    public int lastStoneWeight(int[] stones) {
        // Step 1: Initialize max-heap (use reverseOrder for max-heap)
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        
        // Add all stones to the heap
        for (int stone : stones) {
            maxHeap.offer(stone);
        }
        
        // Step 2: Keep smashing until at most one stone remains
        while (maxHeap.size() > 1) {
            // Extract two heaviest stones
            int first = maxHeap.poll();
            int second = maxHeap.poll();
            
            // Calculate remaining weight
            int remaining = first - second;
            
            // If there's a remaining stone, add it back
            if (remaining > 0) {
                maxHeap.offer(remaining);
            }
        }
        
        // Step 3: Return result
        return maxHeap.isEmpty() ? 0 : maxHeap.peek();
    }
}
```

### Python Implementation

```python
import heapq

class Solution:
    def lastStoneWeight(self, stones):
        # Step 1: Initialize max-heap
        # Python provides only min-heap, so store negative values
        max_heap = []

        # Add all stones to the heap
        for stone in stones:
            heapq.heappush(max_heap, -stone)

        # Step 2: Keep smashing until at most one stone remains
        while len(max_heap) > 1:
            # Extract two heaviest stones
            first = -heapq.heappop(max_heap)
            second = -heapq.heappop(max_heap)

            # Calculate remaining weight
            remaining = first - second

            # If there's a remaining stone, add it back
            if remaining > 0:
                heapq.heappush(max_heap, -remaining)

        # Step 3: Return result
        return 0 if not max_heap else -max_heap[0]
```

### Complexity Analysis

#### Time Complexity: O(n log n)

- Building the initial heap is **O(n)**.
- Each smashing operation involves:
- - Two poll operations: **O(log n) **each.
  - One offer operation (if needed): **O(log n)**.
- In the **worst case**, we perform **n-1** smashing operations.
- Overall, O(n) + O((n-1) × 2 log n) = ***O(n log n)***

### **Space Complexity: **O(n)

- Max-heap stores all **n** **stones** initially.
- As **stones are smashed**, the **heap** **size** **decreases**.
- No additional data structures of significant size.
- Overall space complexity, ***O(n)*****.**
