## Problem Statement

Given two singly linked lists, ***list1*** and ***list2***, your task is to find the union of these two lists. The **union** should contain all unique elements from both ***list1*** and ***list2***. The resulting union should be presented as a new linked list with elements sorted in ascending order.

Each specific element should appear only once in the resulting list, even if it appears in both input lists or multiple times in one list.

### Example 1

> [!NOTE]
> **INFO**
> **Input:** list1 = [10, 15, 4, 20], list2 = [8, 4, 2, 10]
> **Output:** [2, 4, 8, 10, 15, 20]
> **Explanation:** We combine both lists to get all elements: **[10, 15, 4, 20, 8, 4, 2, 10]**. Then we remove duplicates (4 and 10 appear in both lists) to keep only unique values. Finally, we sort them in ascending order: **[2, 4, 8, 10, 15, 20]**.

### Example 2

> [!NOTE]
> **INFO**
> **Input:** list1 = [1, 3, 5], list2 = [2, 4, 6]
> **Output:** [1, 2, 3, 4, 5, 6]
> **Explanation:** We combine both lists to get all elements: **[1, 3, 5, 2, 4, 6]**. There are no duplicates, so we keep all unique values. Finally, we sort them in ascending order: **[1, 2, 3, 4, 5, 6]**.

### Example 3

> [!NOTE]
> **INFO**
> **Input:** list1 = [7, 8, 9], list2 = [5, 6, 7]
> **Output: **[5, 6, 7, 8, 9]
> **Explanation:** We combine both lists to get all elements: **[7, 8, 9, 5, 6, 7]**. We remove the duplicate 7 to keep only unique values. Finally, we sort them in ascending order: **[5, 6, 7, 8, 9]**.

### Constraints

- The number of nodes in each linked list is in the range** [1, 10****4****]**.
- 0 <= **Node.val **<= 105

## Brute-Force Approach

### Intuition

Traverse both linked lists and collect their elements into a HashSet, which automatically ensures uniqueness by ignoring duplicates. First, iterate through list1 and add each node’s value to the HashSet, then traverse list2 and add its elements as well, allowing the set to handle any repeated values. Once all elements are collected, convert the HashSet into an ArrayList and sort it to arrange the values in ascending order. Finally, create a new linked list by iterating over the sorted ArrayList and inserting each element sequentially, resulting in a sorted linked list containing all unique elements from both original lists.

### Algorithm

1. Firstly we** handle edge cases** because we need to avoid null pointer exceptions and handle empty lists correctly. If **both** lists are **null** or **empty** we **return** **null**.  If** list1** is **null** or **empty**, process only** list2**. If **list2** is **null** or **empty**, process only **list1.**
2. Now, we **create a HashSet** to store **unique** **elements** because HashSet automatically prevents duplicates and provides O(1) insertion time.
3. Next, we **traverse list1** and add all elements to the HashSet because we need to collect all elements from the first list. Basically, HashSet ensures duplicates within **list1** are ignored.
4. After covering** list1 **now we **traverse list2** and add all elements to the HashSet because we need to collect all elements from the second list.If an element from list2 already exists (was in list1), HashSet ignores it.
5. **Convert HashSet to ArrayList** because we need to sort the elements, and ArrayList provides easy sorting capabilities.
6. **Sort the ArrayList** in ascending order because the problem requires the result to be sorted. This uses efficient sorting algorithm (TimSort in Java) with O(k log k) complexity where k = unique elements.
7. After this, we build** the result linked list** from sorted ArrayList because we need to return the answer as a linked list.
8. At last, we **return** the head of the newly created **union linked list**.

### C++ Implementation

```cpp
#include <vector>
#include <unordered_set>
#include <algorithm>
using namespace std;

class Node {
public:
    int data;
    Node* next;

    Node(int data) {
        this->data = data;
        this->next = nullptr;
    }
};

class Solution {
public:
    // Brute Force Approach - Using HashSet + Vector
    Node* findUnion(Node* list1, Node* list2) {

        // Step 1: Handle edge cases
        if (list1 == nullptr && list2 == nullptr) {
            return nullptr;
        }

        // Step 2: Create HashSet for unique elements
        unordered_set<int> uniqueElements;

        // Step 3: Traverse list1 and add elements
        Node* current = list1;
        while (current != nullptr) {
            uniqueElements.insert(current->data);
            current = current->next;
        }

        // Step 4: Traverse list2 and add elements
        current = list2;
        while (current != nullptr) {
            uniqueElements.insert(current->data);
            current = current->next;
        }

        // Step 5: Convert HashSet to vector
        vector<int> sortedList(uniqueElements.begin(), uniqueElements.end());

        // Step 6: Sort the vector
        sort(sortedList.begin(), sortedList.end());

        // Step 7: Build result linked list
        Node* dummy = new Node(0);
        current = dummy;

        for (int value : sortedList) {
            current->next = new Node(value);
            current = current->next;
        }

        // Step 8: Return head of result list
        return dummy->next;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(n + m + k log k)

- (where **n** = number of **nodes** in **list1**, **m** = number of **nodes** in **list2** and **k** = number of **unique** **elements** **(k ≤ n + m)).**
- We traverse **list1 once**, visiting all **n** nodes and inserting values into a HashSet. Each insertion takes **O(1)** on average, so this step costs **O(n)**.
- We traverse **list2 once**, visiting all **m** nodes and inserting values into the same HashSet. Again, each insertion is **O(1)** on average, so this step costs **O(m)**.
- After collecting unique elements, we **convert the HashSet to an ArrayList**, which takes **O(k)** time.
- We then **sort the ArrayList** containing **k** elements. Sorting takes **O(k log k)** time and is the **dominant operation**.
- Finally, we **build the result linked list** by creating and linking **k** nodes, which takes **O(k)** time.

#### Space Complexity: O(k)

- (Where:** k** = number of **unique elements**).
- A **HashSet** is used to store unique elements is **O(k)** space.
- An **ArrayList** stores the same **k** elements for sorting is **O(k)** space.
- A few pointer variables are used **O(1)** space.
- The **result linked list** contains **k** nodes (output space, usually not counted).

## Optimal Approach

### Intuition

The brute force approach relies on extra space by using a HashSet and an ArrayList, but this can be optimized by avoiding multiple data structures and handling sorting and duplicate removal together. Although directly merging two linked lists like merge sort would be ideal, this only works if the lists are already sorted, which is not guaranteed here. To handle unsorted lists efficiently, we can collect all elements from both linked lists into a TreeSet. A TreeSet automatically maintains elements in sorted order while removing duplicates at the same time, eliminating the need for a separate sorting step or duplicate removal logic. Each insertion takes O(log⁡k) time, where kk is the number of unique elements, and once all values are inserted, we can directly build the result linked list by traversing the TreeSet, achieving a clean and optimized solution.

### Algorithm

1. Firstly, we handle **edge cases** by checking whether one or **both linked lists** are null to avoid unnecessary processing and prevent runtime errors.
2. Next, we create a **TreeSet **to** store elements from both linked lists** because it automatically removes duplicates and keeps the values in sorted order, which saves us from writing separate logic for these tasks.
3. We then **traverse **the** first linked list** and **insert** each **node’s** value into the TreeSet, followed by **traversing** the **second** **linked** **list** and inserting its values as well, ensuring that all elements from **both** lists are considered while duplicates are ignored.
4. Since the **TreeSet maintains sorted order** internally, no additional sorting or **duplicate-removal** steps are required.
5. Finally, we build the result linked list by iterating over the TreeSet, as its iterator **returns** elements in sorted order, and create new nodes sequentially. **Returning** the **head** of this **new linked list** gives us a **sorted** list containing only unique elements from both **original** **lists**.

### Complexity Analysis

#### Time Complexity: O((n + m) log k)

- (where **n **= number of **nodes** in **list1 **and **m **= number of **nodes** in **list2 **and** k = number **of **unique elements**).
- We traverse **list1 once**, visiting all **n** nodes. Each value is inserted into a **TreeSet**, and since TreeSet is implemented using a **balanced binary search tree**, each insertion takes **O(log k)** time. This step costs **O(n log k)**.
- We traverse **list2 once**, visiting all **m** nodes. Each value is again inserted into the TreeSet, with each insertion costing **O(log k)** time. This step costs **O(m log k)**.
- After collecting all unique elements in sorted order, we **iterate through the TreeSet** to build the result linked list. Iterating through **k** elements and creating nodes takes **O(k)** time.

#### **Space Complexity: **O(k)

- **(where k = number **of **unique elements**).
- A **TreeSet** is used to store all unique elements, requiring **O(k)** space.
- A few pointer variables (such as **dummy** and **current**) use **O(1)** space.
- The **result linked list** contains **k** nodes (output space, usually not counted).
