## Problem Statement

Given a list of points on a 2D plane, each represented as a coordinate ***[x, y]***, and an integer ***k***, your task is to find the ***k*** points closest to the origin ***(0, 0)*** based on their Euclidean distance.

The Euclidean distance from the origin for a point ***(xi, yi)*** is given by the formula:*** distance = √((xi)******2****** + (yi)******2******)***

For efficiency and to avoid precision errors, compare the squared distances of the points instead. The squared distance is calculated by: ***distance^2 = (xi******2****** + yi******2******)***.

Your goal is to return a list of the ***k*** points that have the smallest squared distances from the origin. You can return these points in any order.

### Example 1

> [!NOTE]
> **INFO**
> **Input:** points = [[1, 3], [-2, 2], [5, 8], [0, 1]] k = 2
> **Output:** [[0, 1], [-2, 2]]
> **Explanation:** Point [1, 3]: distance² = 1² + 3² = 1 + 9 = 10 
> 
> Point [-2, 2]: distance² = (-2)² + 2² = 4 + 4 = 8 
> Point [5, 8]: distance² = 5² + 8² = 25 + 64 = 89
> Point [0, 1]: distance² = 0² + 1² = 0 + 1 = 1 
> Sorted by distance: [0,1](1), [-2,2](8), [1,3](10), [5,8](89) 
> K=2 closest points: [[0, 1], [-2, 2]]

### Example 2

> [!NOTE]
> **INFO**
> **Input:** points = [[3, 3], [5, -1], [-2, 4]] k = 2
> **Output:** [[3, 3], [-2, 4]]
> **Explanation:** Point [3, 3]: distance² = 3² + 3² = 9 + 9 = 18 
> 
> Point [5, -1]: distance² = 5² + (-1)² = 25 + 1 = 26 
> Point [-2, 4]: distance² = (-2)² + 4² = 4 + 16 = 20 
> Sorted by distance: [3,3](18), [-2,4](20), [5,-1](26) 
> K=2 closest points: [[3, 3], [-2, 4]]

### Example 3

> [!NOTE]
> **INFO**
> **Input:** points = [[1, 1], [1, -1], [-1, 1], [-1, -1]] k = 3
> **Output: **[[1, 1], [1, -1], [-1, 1]] (or any 3 of these)
> **Explanation:** All 4 points have the same distance from origin: 
> distance² = 1² + 1² = 2 Any 3 points are valid answers since order doesn't matter.

- -**10****4** <= xi, yi <= **10****4**

## Real-Life Analogy

Imagine you are a **drone delivery service dispatcher** at your warehouse (located at coordinates 0, 0). You have multiple delivery locations on your 2D map, and you need to prioritize the **k nearest deliveries** to minimize travel time.

**Scenario: Your Warehouse:** Located at origin (0, 0)

**Delivery Locations:**

- Customer A: (1, 3) → distance = √10 ≈ 3.16 km
- Customer B: (-2, 2) → distance = √8 ≈ 2.83 km
- Customer C: (5, 8) → distance = √89 ≈ 9.43 km
- Customer D: (0, 1) → distance = √1 = 1 km

**Task:** Prioritize 2 nearest deliveries (k=2)

**Solution:**

1. Customer D (1 km)
2. Customer B (2.83 km)

**Why squared distance?**

- Comparing √1 vs √8 vs √10 requires expensive calculations
- Comparing 1 vs 8 vs 10 gives same ordering, faster!

## Brute-Force Approach

### Intuition

The most straightforward solution is to compute the squared distance of each point from the origin, sort all points based on these distances, and then select the first **k** points from the sorted list. While this approach is easy to understand and implement, it becomes inefficient when **k** is much smaller than **n** (the total number of points), because sorting all points takes unnecessary time even though only the closest **k** points are needed.

### Algorithm

1. First, we calculate the distance of every point from the origin because we must know how far each point is in order to compare which ones are closest. For a point [x,y], we compute the **squared distance** x2 + y2 instead of the actual distance, since the square root does not change the relative ordering and avoiding it makes the computation faster. Each point is then stored along with its computed distance so that we can sort and retrieve them together.
2. Next, we sort all the points in **ascending order of their distances** because the problem asks for the closest points to the origin. Sorting ensures that points with smaller distances appear first in the list, making it easy to identify the nearest ones. The sorting criteria prioritize distance as the primary key, so any point closer to the origin will always come before a farther one.
3. Finally, after sorting, we select the first **k** points from the list because these positions are guaranteed to contain the **k nearest points**. Since the list is already ordered from closest to farthest, taking elements from index **0** to **k-1** directly gives the required result, which we then return as the final answer.

### Code

### C++ Implementation

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        // Step 1: Create list to store points with distances
        vector<vector<int>> pointsWithDist;

        for (auto& point : points) {
            int x = point[0];
            int y = point[1];
            int distSquared = x * x + y * y;

            // Store point with its squared distance
            pointsWithDist.push_back({x, y, distSquared});
        }

        // Step 2: Sort by distance (3rd element = distance²)
        sort(pointsWithDist.begin(), pointsWithDist.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[2] < b[2];
             });

        // Step 3: Extract first k points
        vector<vector<int>> result;

        for (int i = 0; i < k; i++) {
            result.push_back({pointsWithDist[i][0], pointsWithDist[i][1]});
        }

        // Step 4: Return result
        return result;
    }
};
```

### Complexity Analysis

#### Time Complexity: O(n log n)
(where **n** = number of **points**).

- We iterate through all **n** points once to compute the squared distance (**x² + y²**), which is a constant-time operation. This step takes **O(n)** time.
- We sort all **n** points based on their computed distances. Sorting **n **elements requires **O(n log n)** time, and each comparison is **O(1)**. This is the **dominant operation**.
- After sorting, we extract the first **k** points. Copying **k** points takes **O(k)** time, where **k ≤ n**.

#### Space Complexity: O(n)

- (where **n** = number of **points**).
- A separate list/array is used to store all **n** points along with their distances, which requires **O(n)** space.
- The sorting algorithm (TimSort) uses **O(n)** auxiliary space in the worst case.
- The result array stores **k** points, which is output space and usually not counted.
- Only a few variables are used otherwise, which take **O(1)** space.

## Optimal Approach

### Intuition

The brute-force approach sorts all **n** points even though only the **k closest** are required, which is inefficient when **k << n**. A more optimal strategy is to use a **max-heap of size k** to keep track of only the best candidates seen so far. As we iterate through the points, each point’s squared distance from the origin is computed and compared against the farthest point currently in the heap. The heap’s top always represents the **maximum distance among the k closest points**, making it easy to decide whether a new point is better. If the heap contains fewer than k points, the new point is added directly; otherwise, if the new point is closer than the heap’s maximum, the farthest point is removed and the new one is inserted. By the end of the iteration, the heap contains exactly the **k closest points**, achieving an efficient time complexity of **O(n log k)** instead of **O(n log n)**.

### Algorithm

1. **Initialize a max-heap of capacity k** because we want to keep track of only the k closest points at any time. Using a max-heap ensures that the point farthest from the origin among the current k candidates is always easily accessible and removable.
2. **Iterate through each point in the input set** since every point is a potential candidate for being among the k closest and must be evaluated at least once.
3. **Compute the squared distance of the current point from the origin** to measure how close it is. Squared distance is sufficient for comparison purposes and avoids unnecessary computational overhead from square root operations.
4. **Insert the point along with its distance into the heap** so that it can be compared against other candidates based on distance. This allows the heap to maintain an ordered structure relative to closeness.
5. **Maintain the heap size at k** because we only need the k closest points, not all of them. Whenever the heap size exceeds k, remove the farthest point (the maximum element in the max-heap). This step ensures that less optimal candidates are discarded immediately.
6. **Continue this process for all points** so that, by the end of the iteration, the heap contains only the k closest points encountered across the entire dataset.
7. **Collect the points stored in the heap** into the result structure, since the heap now represents the final set of k closest points. The internal order of the heap does not matter because the problem does not require the output to be sorted.
8. **Return the collected points** as the final answer, as they are guaranteed to be the k closest points to the origin.

### Code

### C++ Implementation

```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        // Step 1: Create Max-Heap (largest distance at top)
        priority_queue<vector<int>> maxHeap;

        // Step 2: Process each point
        for (auto& point : points) {
            int x = point[0];
            int y = point[1];

            // Step 3: Calculate squared distance
            int distSquared = x * x + y * y;

            // Step 4: Add point to heap with distance
            maxHeap.push({distSquared, x, y});

            // Step 5: Maintain heap size = k
            if (maxHeap.size() > k) {
                maxHeap.pop();  // Remove farthest point
            }
        }

        // Step 6 & 7: Extract k points from heap
        vector<vector<int>> result;

        while (!maxHeap.empty()) {
            vector<int> point = maxHeap.top();
            maxHeap.pop();

            result.push_back({point[1], point[2]});
        }

        // Step 8: Return result
        return result;
    }
};
```

### Java Implementation

```java
import java.util.*;

class Solution {
    public int[][] kClosest(int[][] points, int k) {
        // Step 1: Create Max-Heap (largest distance at top)
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>(
            (a, b) -> (b[2] - a[2])  // Compare by distance² (descending)
        );
        
        // Step 2: Process each point
        for (int[] point : points) {
            int x = point[0];
            int y = point[1];
            
            // Step 3: Calculate squared distance
            int distSquared = x * x + y * y;
            
            // Step 4: Add point to heap with distance
            maxHeap.offer(new int[]{x, y, distSquared});
            
            // Step 5: Maintain heap size = k
            if (maxHeap.size() > k) {
                maxHeap.poll();  // Remove farthest point
            }
        }
        
        // Step 6 & 7: Extract k points from heap
        int[][] result = new int[k][2];
        int index = 0;
        
        while (!maxHeap.isEmpty()) {
            int[] point = maxHeap.poll();
            result[index][0] = point[0];  // x
            result[index][1] = point[1];  // y
            index++;
        }
        
        // Step 8: Return result
        return result;
    }
}
```

### Python Implementation

```python
import heapq

class Solution:
    def kClosest(self, points, k):
        # Step 1: Create Max-Heap (largest distance at top)
        max_heap = []

        # Step 2: Process each point
        for point in points:
            x = point[0]
            y = point[1]

            # Step 3: Calculate squared distance
            dist_squared = x * x + y * y

            # Step 4: Add point to heap with negative distance
            # Python has a min-heap, so use negative value for max-heap behavior
            heapq.heappush(max_heap, (-dist_squared, x, y))

            # Step 5: Maintain heap size = k
            if len(max_heap) > k:
                heapq.heappop(max_heap)  # Remove farthest point

        # Step 6 & 7: Extract k points from heap
        result = []

        while max_heap:
            _, x, y = heapq.heappop(max_heap)
            result.append([x, y])

        # Step 8: Return result
        return result
```

### Complexity Analysis

#### Time Complexity: O(n log k)
(where **n **= total number of **points,** ** k = number **of **closest points required**).

- We iterate through all **n** points once. This loop runs **n times**.
- For each point:  - Squared distance (**x² + y²**) is calculated in **O(1)** time.
  - The point is inserted into the heap in **O(log k)** time.
  - If the heap size exceeds **k**, one element is removed in **O(log k)** time.
  - Hence, the total cost per point is **O(log k)**.
- After processing all points, we extract **k** points from the heap.  - Each extraction takes **O(log k)** time.
  - Total extraction cost is **O(k log k)**.
  - Since **k ≤ n**, this does not dominate the total time.

### **Space Complexity: **O(k)

- **(where k = number **of **closest points**).
- The max-heap stores at most **k** elements at any time, which requires **O(k)** space.
- The result array also stores **k** points, which is output space and not counted.
- Only a constant number of variables are used otherwise, requiring **O(1)** space.
