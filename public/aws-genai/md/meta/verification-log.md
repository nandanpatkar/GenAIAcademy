## 11. Bedrock model customization ✅ (read 2026-10-23)

- **Three methods:** supervised fine-tuning, **reinforcement fine-tuning** (reward functions via Lambda; can start from invocation logs), and **distillation** (teacher → student). The course lessons 11–12 cover fine-tuning only. Continued pre-training is **not listed** on the current overview page (it was in earlier docs), so treat it as ❌ unverified/possibly retired and check before relying on it.
- **Billing:** training billed on *tokens in the training corpus × epochs*, plus **monthly storage per custom model**.
- **Deployment of a custom model:** (a) **Provisioned Throughput** (dedicated capacity) or (b) **custom model deployment for on-demand inference** (pay per use; invoke via the deployment ARN). Older material says Provisioned Throughput is mandatory; that is no longer the only option.
- **Fine-tunable models (page snapshot):** Amazon Nova family, Titan Image Generator G1 v2, Titan Multimodal Embeddings G1, Anthropic Claude 3 Haiku, Meta Llama 3.1/3.2/3.3. Mostly single-Region (us-east-1 or us-west-2). Lists change; always re-check.
- **Data format:** `.jsonl`. Non-conversational: `{"prompt": ..., "completion": ...}`. Conversational (Converse-style): `schemaVersion: "bedrock-conversation-2024"` with `system` and `messages`. Claude 3 Haiku uses its own `system` + `messages` string format. Planning ratio from AWS: **~6 characters per token** for dataset sizing. Claude 3 Haiku: min 32 records, max 10,000 total, 32,000 tokens per record; Llama 3.x: min 100 records.
- The page does **not** state which technique (e.g. LoRA) Bedrock uses internally per model. LoRA is explained in this repo as a concept (and for SageMaker, which the exam guide names in skill 1.2.4).
- Sources: `custom-models.html`, `custom-model-fine-tuning.html`, `model-customization-use.html`, `model-customization-prepare.html`.

## 12. Bedrock Knowledge Bases details ✅ (read 2026-10-23)

- **Managed KB:** `CreateKnowledgeBase` with `type: MANAGED`; `managedKnowledgeBaseConfiguration.embeddingModelType` = `MANAGED` (default, service model, **no Bedrock model access needed**) or `CUSTOM` (needs `embeddingModelArn` + dimensions **1024**, float32). **Cannot change embedding type after creation.** With a custom embedding model the **managed reranker is unavailable**. Query with `Retrieve` and **`managedSearchConfiguration`** (not `vectorSearchConfiguration`, which is for custom KBs). Creation takes ~2–5 minutes. Console path is under **Amazon Bedrock AgentCore → Built-in tools → Knowledge Base**.
- **Quotas (managed):** 200 data sources/KB (adjustable), 50 concurrent ingestion jobs, 10 TB raw storage (adjustable), 10,000 query characters, **600 Retrieve RPM per KB** (burst 25 RPS), 300 `AgenticRetrieveStream` RPM per account.
- **Customer-managed KB:** you pick the vector store; connectors only **S3 and Custom**; parsing: Default, Foundation Model, or **Bedrock Data Automation**; no agentic retrieval; no AgentCore Gateway integration.
- **Chunking:** default ≈ 300 tokens (sentence-aware); fixed-size (max tokens + overlap %); hierarchical (parent/child max tokens + overlap tokens; child retrieved then **replaced by parent**, so fewer results than requested); semantic (max tokens, buffer size, breakpoint percentile; **extra foundation-model cost**); none. Tables/figures in parsed content can attach page/table context (≤10,000 characters).
- **Search types:** HYBRID / SEMANTIC via `overrideSearchType`; hybrid only for RDS, OpenSearch Serverless, MongoDB vector stores with a filterable text field, otherwise semantic.
- **Metadata filters:** `equals, notEquals, greaterThan(OrEquals), lessThan(OrEquals), in, notIn, startsWith (OpenSearch Serverless only), stringContains, listContains`; combine with `andAll`/`orAll` (up to 5, one nesting level). Managed KBs: **no `startsWith`/`stringContains`**. OpenSearch Serverless index must use the **`faiss`** engine (not `nmslib`) for filtering. S3 metadata via `<file>.metadata.json`.
- **Guardrails apply to the input and the generated response only, not to retrieved references** (important exam trap).
- **Query decomposition:** `orchestrationConfiguration.queryTransformationConfiguration.type = QUERY_DECOMPOSITION`.
- **Reranking:** `rerankingConfiguration` in the vector search configuration.
- Doc inconsistencies to keep in mind: the Kendra migration page shows a `create_knowledge_base` example without `embeddingModelType`, while the KB page documents `embeddingModelType`; and the connector list is 7 on some pages and 12 (adds Box, Salesforce, ServiceNow, Zendesk, Confluence variants) on the create page. I follow the dedicated KB pages and tell you where they differ.
- Sources: `knowledge-base.html`, `kb-how-it-works.html`, `kb-build-managed.html`, `kb-managed-create.html`, `kb-managed-prereqs.html`, `kb-managed-quotas.html`, `kb-test-config.html`, `kb-test-retrieve-generate.html`, `kb-chunking.html`, `knowledge-base-supported.html`.

## 14. Bedrock Guardrails ✅ (read 2026-10-23)

- **Safeguards:** content filters (Hate, Insults, Sexual, Violence, Misconduct, Prompt Attack; text and image), **denied topics**, **word filters** (case-insensitive whole word/phrase; profanity list), **sensitive information filters** (PII + custom regex; block or mask), **contextual grounding checks** (grounding + relevance), **Automated Reasoning checks**.
- **Tiers:** Classic (English/French/Spanish) vs **Standard** (more languages, code-aware, prompt-leakage detection, requires **cross-Region inference**; denied-topic definition limit 1,000 vs 200 chars). Tiers apply to content filters/prompt attacks, denied topics, contextual grounding. Contextual-grounding Standard is available in a smaller Region set; elsewhere → `ValidationException`. **No tier specified = Classic.** `UpdateGuardrail` replaces the whole policy config: omit `tierConfig` and it resets to Classic.
- **Denied topics:** up to **30** topics, definition ≤200 chars (Classic), ≤5 sample phrases of ≤100 chars; don't write instructions, negatives/exceptions, or entity/word lists in a definition; **evaluation order can change outcomes**.
- **Converse integration:** `guardrailConfig {guardrailIdentifier, guardrailVersion, trace}`; `ConverseStream` adds `streamProcessingMode` (`sync` default | async). Blocked → `stopReason = guardrail_intervened`, blocked message in `output`. **Once any `guardContent` block exists, only `guardContent` is evaluated** (system prompt evaluated only if wrapped in `guardContent`). **Tool-use fields (`toolResult`, `toolSpec`, `toolUse.input`) are not evaluated** by content/topic/word/PII filters.
- **Masking:** `ANONYMIZE` replaces with `{NAME}`/`{EMAIL}` etc., still reports `stopReason = guardrail_intervened` (use trace `action: ANONYMIZED` to tell masking from blocking). **Trace contains the unmasked `match` values and `modelOutput`**, and **model invocation logs always contain the original input**: protect with CloudWatch log data protection. **Masking is not supported in asynchronous streaming mode.**
- **Contextual grounding:** thresholds **0–0.99** (1 invalid); limits **100,000** chars source, **1,000** query, **5,000** response; needs grounding source + query + content to guard; qualifiers `grounding_source`, `query`, `guard_content`; checks run on **output only**. Relevance: if any chunk is relevant the whole response counts as relevant; with streaming an irrelevant response may be flagged only after fully streamed.
- **ApplyGuardrail:** `source` INPUT|OUTPUT, no model invoked; permission is only `bedrock:ApplyGuardrail` on the guardrail ARN; `outputScope: FULL` returns undetected entries too. Response `action`: `GUARDRAIL_INTERVENED | NONE`.
- **Automated Reasoning checks:** formal-logic validation against a policy built from a source document (≤5 MB / 50,000 chars); **detect mode only**; **English (US) only**; **no streaming**; **no prompt-injection protection**; plaintext only (Base64 etc. may skip evaluation); validity covers only variables in the policy; GA Regions: us-east-1/2, us-west-2, eu-central-1, eu-west-1/3, ap-southeast-2; billed per validation request; cross-Region inference within the geography. Result names confirmed on the page: `VALID`, `TRANSLATION_AMBIGUOUS`, `TOO_COMPLEX`; the full list is ❌ not confirmed here.
- **"Token-level redaction" (course lesson 26; exam guide skill 3.3.4):** I found **no built-in Bedrock feature with that name**. Verified building blocks: guardrail masking (`ANONYMIZE`), CloudWatch log data protection for invocation logs, and (🟡 AWS ML blog) custom **tokenization** that swaps masks for format-preserving tokens via your own service.
- **Not verified:** condition key to *enforce* guardrail use in IAM (I believe `bedrock:GuardrailIdentifier` exists), guardrail pricing numbers, word-filter and image-filter limits.
- Sources: `guardrails.html`, `guardrails-use-converse-api.html`, `guardrails-sensitive-filters.html`, `guardrails-contextual-grounding-check.html`, `guardrails-content-filters.html`, `guardrails-denied-topics.html`, `guardrails-tiers.html`, `guardrails-streaming.html`, `guardrails-use-independent-api.html`, `guardrails-permissions.html`, `guardrails-automated-reasoning-checks.html`.

## 15. Multimodal inputs, BDA, Transcribe ✅ (read 2026-10-23)

- **Converse content blocks:** `text`, `image`, `document`, `video` (also `cachePoint`, `toolUse`, `toolResult`, `guardContent`). Images/videos by **`bytes`**; **only Amazon Nova models accept an S3 URI** for images (others reject it with a validation error); videos accept `s3Location` (role needs `s3:GetObject`, `bucketOwner` if not your bucket). Documents need an explicit **`format`** (not inferred), **must be accompanied by a `text` block**, and the `name` must be neutral (prompt-injection risk). With `citations` enabled: `txt`/`pdf` only and no `s3Location`. Bedrock doesn't store your content.
- **Bedrock Data Automation (BDA):** managed extraction of structured data from documents, images, audio, video (document processing, media analysis, RAG enrichment); built-in **visual grounding and confidence scores**. API names and blueprints are covered in `02-data-management`.
- **Amazon Transcribe:** speech-to-text; **batch** (S3 files) or **streaming**; billed per second of audio; PII redaction and custom language models cost extra; Region support differs between batch and streaming and between Transcribe, Transcribe Medical and Call Analytics.
- **Nova Multimodal Embeddings** cannot process speech content directly; use BDA/Transcribe to get text first (per the KB retrieve page).

## 16. Prompt Management, Flows, structured outputs ✅ (read 2026-10-23)

- **Prompt Management:** `{{variable}}`; variants (console compares up to 3); `TEXT` vs `CHAT` template (`CHAT` required for prompt caching); draft saved on every save, **versions are immutable snapshots**; target can be a model, inference profile, or agent (`genAiResource`, console-test only); optional customer-managed KMS key. `CreatePrompt` requires `name`, `variants`, `defaultVariant`. Runtime: put `arn:aws:bedrock:<region>:<acct>:prompt/<ID>:<version>` in Converse `modelId` and fill `promptVariables` (`{"var": {"text": "value"}}`). The docs say prompts are integrated into applications "with the help of Amazon Bedrock Flows" or by specifying the prompt in inference.
- **"Approval workflows" (exam guide skill 1.6.3):** no built-in approval feature found in the Prompt Management pages ❌. Treated as a process (versions + IAM + pipeline approvals + CloudTrail).
- **Flows:** nodes Input, Output, Prompt, Agent, Knowledge base, S3 storage, S3 retrieval, Lambda function, Condition, Iterator, Collector, DoWhile, Lex, Inline code (**preview**, Python 3.12, ≤5 per flow, not in async executions, ≤25 running per account, ≤5 MB, no `print` capture). Conditions evaluated in order; `default` branch; Iterator is sequential; DoWhile `maxIterations` default 10; Lex node single-utterance only; KB-node guardrails only in `RetrieveAndGenerate` mode. New flow has `DRAFT` and test alias `TSTALIASID`; versions immutable and numbered from 1; apps call `InvokeFlow` on an alias; rollback by repointing alias; async "flow executions" and multi-turn "converse with a flow" exist. Node `type` capitalization is inconsistent on the page (`Input`/`Output` vs `prompt`), so I do not publish a full flow-definition JSON.
- **Structured outputs:** Converse `outputConfig.textFormat` (`type: json_schema`, `structure.jsonSchema {name, description, schema (JSON *string*)}`); InvokeModel Claude `output_config.format` (schema as object); open-weight `response_format`; **strict tool use** via `"strict": true`. Draft 2020-12 **subset**: no recursion, no external `$ref`, no `minimum/maximum/multipleOf`, no `minLength/maxLength`, `additionalProperties` only `false`; `minItems` only 0/1; listed string formats. Unsupported → **400**; first-time grammar compile up to a few minutes; **cached 24 h** per identical schema/account; works with Converse(+stream), InvokeModel(+stream), cross-Region inference, batch; **incompatible with Anthropic citations (400)**; some geographic profiles unsupported for some models. 🟡 (search summary of AWS blog, not opened): GPT-family models on Converse may need an extra `strict` flag; check `stop_reason` before parsing.

## 17. Prompt engineering, injection guidance, enterprise integration, Generative AI Lens ✅ (read 2026-10-23)

- **Prompt engineering (AWS page):** prompt components = task/instruction, context, demonstration examples, input text; few-shot = in-context learning; prompt templates use `{{placeholders}}`; models don't recall prior requests unless included. The page still shows the legacy Claude `\n\nHuman: … \n\nAssistant:` wrapping for API prompts; that applies to the older text-completion style, and Converse uses role-based `messages`. Hallucination advice: refine the prompt, use RAG, or change model.
- **Prompt injection (AWS Security Blog):** direct vs **indirect** (white-on-white text in an uploaded document is the AWS example); layers = Guardrails (incl. prompt attack filter) at multiple points, input validation + **AWS WAF**, prompt templates ("parameterized queries"; XML tags help), IAM role mapping so damage is constrained, monitoring. **CloudTrail does not log inference content**; use **model invocation logs** and guardrail tracing. System prompts "don't provide absolute control". The blog does **not** explicitly recommend human approval; I label that as general practice.
- **Bias/fairness in prompting:** I found **no dedicated AWS guidance page** ❌. The mitigation list in `01/09` is general practice aligned with exam skill 3.4.2.
- **Data protection (Bedrock):** shared responsibility; **TLS 1.2 required (1.3 recommended)**; model providers have **no access** to the Bedrock-operated model deployment accounts, hence no access to Bedrock logs, prompts or completions; don't put confidential data in tags/name fields.
- **PrivateLink:** interface endpoints for `bedrock`, `bedrock-runtime`, `bedrock-mantle`, `bedrock-agent`, `bedrock-agent-runtime`, plus `bedrock-fips` / `bedrock-runtime-fips` (FIPS in us-east-1/2, us-west-2, ca-central-1, GovCloud); private DNS = no code change, otherwise pass the `vpce` URL as `endpoint_url`; **default endpoint policy allows full access**.

## 18. Module 02 data management ✅ (read 2026-10-26)
