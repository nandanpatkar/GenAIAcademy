Introduction to Amazon Connect Routing

Lesson introduction

Call routing is a contact center management feature where incoming contacts are directed to the agent with the most appropriate skill set to handle that contact. The contacts can be queued or sent directly to an agent based on defined business criteria. 

This lesson introduces the key concepts, terminology, and benefits of Amazon Connect routing.

Concepts and terminology

Amazon Connect is an omnichannel contact center that routes contacts. Throughout this course, the term contact is used to describe a user interacting on any of the channels available in Amazon Connect. These channels include voice calls, chats, tasks, and SMS. 

To learn more about the common terminology used when discussing Amazon Connect routing, explore the following seven categories.


Flow
A contact is routed using a flow. The flow defines the routing logic and decisions that drive contacts (voice, chats, and tasks) through the contact center. Flows use customer attributes to make routing decisions or personalize contact experiences. For example, in a flow, the contact hears a personalized greeting with their name and is routed to the appropriate queue.


Queue
Contacts wait in a queue before being routed to and accepted by agents. A queue is typically mapped to a skill that an agent has. Queues work the same for all channels supported in Amazon Connect.


Routing profile
A routing profile represents the skill set and competencies of an agent. Queues are grouped into routing profiles. The queues associated with a routing profile have priorities and delays. The routing profile determines which types of contacts an agent can receive and the routing priority. Consider the following:

Each agent is assigned one routing profile.

A routing profile can have multiple agents assigned to it.


Agent
An agent is a person who handles contacts. In Amazon Connect, the term agent is used interchangeably with the term user. Agents have one routing profile, which determines the queues and channels the agent can receive contacts on.


Agent status
Agents in Amazon Connect have a status that can be manually set in the Amazon Connect Contact Control Panel (CCP). There are two default statuses: Offline and Available. Custom statuses can be created by administrators. Inbound contacts can only be routed to agents when their status is Available. Agents can make outbound calls by putting their status to a nonproductive custom status, such as Meeting or Lunch. Technically, agents can make outbound calls when they are in the Offline status as well.


Quick connects
Quick connects make it possible to create lists of common transfer destinations. For example, a bank can set up IT Help as a quick connect. If a loans agent receives a browser issue call, they can transfer it to IT Help through the quick connect list. Quick connects provide efficient call routing to relevant teams or resources.


Channel
A channel is a mechanism that a contact uses to interact with the contact center. Channels include voice, chats, tasks, and SMS.

Benefits of Amazon Connect routing

Amazon Connect routing offers organizations benefits, including a unified experience across channels, efficient routing to appropriately skilled agents, and seamless scalability based on demand.

Unified experience across channels

Amazon Connect routes contact channels, such as voice calls, chats, tasks, and SMS, through the same routing engine and queues. With routing profiles, queues, and flows, organizations build and maintain core contact experiences across different contact methods. Contacts access services and products on their preferred contact channels. Administrators reuse experiences and integrations, such as data retrieval, to provide seamless contact interactions across channels.

Scenario – Providing multiple contact options
Mary Major visits the AnyCompany website for assistance with a recent purchase. Instead of being limited to calling a hotline, Mary notices a chat option on the website. She initiates a chat session to inquire about her order status. Behind the scenes, Amazon Connect seamlessly routes her chat to the same routing engine and queues as voice calls, ensuring a consistent experience across channels. 



The agent handling the chat, Pat Candella, has access to the same contact data, integration systems, and knowledge base as agents handling voice calls. This means Pat can quickly retrieve Mary's order details, review account history, and provide personalized assistance, just as he does on voice calls. 



If Mary's preferred contact method changes during the interaction, Pat can transition the conversation to another channel, such as voice or SMS. This is done without losing the context or data gathered so far.



Saanvi Sarkar, an AnyCompany supervisor, monitors and manages the contact experience across channels using the same tools and dashboards. This reduces the complexity of optimizing routing efficiency across different contact methods. With this unified approach, AnyCompany can reuse integrations, optimize resource allocation, and continuously improve the overall contact experience across all channels.

Efficient routing to appropriately skilled agents

With routing profiles, organizations configure contact priority and routing to agents based on agent skills, queue priorities, contact attributes, and real-time metrics. Contacts receive support without being transferred across channels. Administrators focus on optimizing contact outcomes instead of adjusting for shifts in contact volumes.

Scenario – Dynamic routing meets operational needs
Mary's chat request is automatically prioritized and routed to Pat, who specializes in order management. Because Mary's chat relates to an order management issue, the routing profile ensures that her request is sent to an appropriately skilled agent.



Mary is also a high-value contact for AnyCompany. With flows and contact attributes, her status gives her chat request a higher priority, ensuring that she receives prompt assistance. Additionally, her loyalty status with AnyCompany means that she can change the destination of her order without additional charges.



Pat is trained in AnyCompany's ordering operations and quickly addresses Mary's request. Pat follows the procedure to change the destination for Mary's order without additional charges.



Real-time metrics, like queue lengths and agent availability, are factored into the routing process. Saanvi, a supervisor, notices an influx of order management queries. The routing profile dynamically handles the influx with predefined priorities, maintaining efficient contact support.



Saanvi focuses on communicating with the operations team to understand the influx instead of actively managing the increase in contacts. Efficient routing and multiple options for real-time prioritization make it possible for AnyCompany to focus on business objectives while managing operational overhead.

Seamless scalability based on demand

With routing profiles, flows, and real-time metrics, business operations scale based on current volumes. Organizations establish contact experience and business workflows, and the system scales up during peak demand without additional application or hardware management. Contacts experience consistent service outcomes during busy periods. Administrators focus on agent performance and contact feedback without monitoring available application or hardware capacity.

Scenario – Handling increased demand and contact outcomes
One of Mary's orders is shipped from overseas, where an unexpected weather event impacts a large number of AnyCompany's incoming deliveries. As AnyCompany experiences a surge in status update inquiries, AnyCompany's implementation of Amazon Connect dynamically adjusts to meet the increased volume of contacts.



Based on available agents and visibility into queues across all channels, Mary is offered alternative communication methods through the AnyCompany website. She can also opt-in to receive updates over SMS as they become available. 



As the number of incoming calls and chat requests start to rise, Amazon Connect automatically distributes interactions to the appropriate agents. Pat continues to receive interactions that require his knowledge and skills, and the bulk of status update inquiries are deflected or provided automatically.



AnyCompany can efficiently onboard and configure additional agents through the Amazon Connect web interface without provisioning or administering licenses or seats. New agents can immediately start handling contacts without any delays due to hardware or application scaling limitations. 



Saanvi assigns routing profiles to the new agents, and the Amazon Connect routing engine dynamically adjusts to the increased number of agents. Contact distribution based on configured rules and agent availability handles the increased demand without configuration changes.

Understanding queues

Agents are configured as users in Amazon Connect. Agents are trained to handle different types of contacts. Their skill sets vary based on their tenure, experience, and exposure to more or less complex interactions. Amazon Connect queues typically reflect an agent's skill set, but you have flexibility to define the queue criteria that works for you. For example, in a financial institution, some agents might be more skilled at handling checking and savings account-related inquiries. Others might specialize in loans and mortgages.

Businesses might want to route contacts to specific agents based on certain criteria, such as the skill set of the agent. This is called queue-based routing or skills-based routing. The following image is an example of skills-based routing.

Single channel routing

In Amazon Connect, contacts are routed based on the agent's routing profile, the hours of operation for a queue, and the routing logic in flows. Contacts get prioritized automatically and routed to the agent who has been idle the longest. If no agents are available, contacts wait in the queue and get serviced in the order they entered the queue. Additional agents can become eligible for routing based on the agent's status or routing profile.

Contacts are routed using the following criteria:

Multiple channel routing

Agents can handle voice, chats, and tasks in Amazon Connect. Routing profiles include one or more queues configured across one or more channels.

With routing profiles, you can configure the rules for delivering multiple contacts across multiple channels. For example, an agent can handle one voice call or three simultaneous chats.

Routing profile configuration for cross-channel concurrency with configuration values for one voice call and three chats.
The second configuration option available in the routing profiles is the cross-channel concurrency. The routing engine uses this setting to decide whether to route more than one contact at the same time to agents. You can configure the routing profile of an agent to get one contact at a time and not get interrupted by other incoming contacts. You can also combine settings to deliver multiple concurrent chats but no voice calls. The following screenshot depicts a routing profile configuration that drives the following routing behavior:

If the agent gets a chat, based on their configuration, they can get up to three chats if the chat queue is busy. 
The chats are not interrupted by voice calls.

When using cross-channel concurrency, Amazon Connect checks which contact to offer the agent as follows:

Amazon Connect checks which contacts and channels the agent is currently handling.

Based on the channels the agent is currently handling and the cross-channel configuration in the agent's routing profile, Amazon Connect determines whether the agent can be routed to the next contact.

Amazon Connect prioritizes the longest waiting contact if the priority and the delay are equal. Even though Amazon Connect is evaluating multiple channels at the same time, FIFO is still respected.

Queue-based routing

With the built-in queue-based routing algorithms, you can route contacts to agents based on the agents' skills. This routing strategy is called queue-based routing or skills-based routing.

For example, an airline can have agents handling English-speaking contacts or Spanish-speaking contacts. They can also have a group of agents handling both language contacts but only over the phone. You can assign the same routing profile to multiple agents. You can also assign multiple queues to a routing profile or assign a queue to multiple routing profiles.

For agents with multiple skills, you assign multiple queues to a routing profile. The same queue can belong to multiple routing profiles. With this strategy, you can define overflow logic.

Proficiency routing

Proficiency routing is another built-in Amazon Connect routing strategy. It uses the standard queue-based routing construct but adds a more flexible and granular approach to selecting agents. You can set up proficiency routing in four steps as follows:

1
Create predefined attributes: In this step, you define the attributes you want to use to make a routing decision. The predefined attributes created here can be used individually or combined by using the AND or OR operators to form a routing step.

2
Assign proficiencies to agents: You select predefined attributes and associate them with an agent. All available agents that meet a routing step requirement of a contact within the same queue are considered for a match.

3
Set routing criteria: Using a flow block, you can set routing criteria manually or dynamically.

4
Transfer to the queue: Send the contact to the queue, where it is evaluated against your routing criteria.

Changing contact priority

In addition to prioritizing contacts within a routing profile, you can dynamically move a contact to the front or back of the queue. Amazon Connect flows include a Change routing priority / age flow block. With this flow block, you can change a contact's position in the queue. 

Screenshot of the Change routing priority / age flow block flow block.
Change routing priority / age flow block

Use this block to implement the business logic that works for your use case. You can move a contact to the back or the front of the queue based on contact data. For example, you can prioritize contacts using your mobile app over contacts using the traditional phone lines.

The default priority for contacts is 5. By setting a priority of 1, you move the contact ahead of other contacts in the queue, so it gets served faster. To do so, change the Set priority value to 1.

You can also adjust the priority of a contact by changing the age of the contact. Use the Adjust by time option to add or subtract time from the original contact start time. When using this option, you artificially change the time in queue for the contact. The system interprets the contact's time in queue as longer or shorter than it actually is and routes accordingly.

Scenario: Time-of-day routing with Amazon Connect
AnyCompany, a leading service provider, uses Amazon Connect to handle inquiries and support requests. The company wants to implement time-of-day routing to ensure efficient resource allocation and a superior experience.


AnyCompany receives a high volume of calls during specific time periods, such as business hours and weekends.

 

To optimize resource allocation, AnyCompany configures the Amazon Connect time-of-day routing feature. This makes it possible to define routing strategies based on time and day.

 

During business hours (Monday to Friday, 9 AM to 5 PM), incoming calls are routed to dedicated service representatives. These agents are trained to handle various queries and issues during peak call volumes.

 

Outside business hours (evenings and weekends), call volumes are lower, and queries are often more straightforward. AnyCompany routes these calls to a separate queue handled by part-time agents or virtual Amazon Lex agents for common queries and basic support.

 

Complex or high-priority calls are escalated to a specialized team of senior agents, regardless of time. This ensures that critical issues are promptly addressed by experienced professionals, even during off-peak hours.

 

By implementing time-of-day routing, AnyCompany effectively manages resources, reduces operational costs, and provides a consistent experience across different times of day.

Security

Amazon Connect provides a number of security features to consider as organizations develop and implement their own security policies. Best practice recommendations include the following: 

Ensure that all profile permissions follow the principle of least privilege.
Set a service control policy (SCP) to prevent the deletion of critical resources.
A security profile is a group of permissions that map to a common role in a contact center. There are security profile permissions related to routing that determine who can create, edit, and view resources like routing profiles, queues, or predefined attributes.

Screenshot of Security profiles permissions for Amazon Connect routing.
As a best practice recommendation, administrators must only grant users access to resources that are absolutely required for their role. For example, a routing strategy designer might only need access to add and modify queues and routing profiles. They only need view access to hours of operation or predefined attributes. 


Routing profiles
This security profile defines user access to the Routing profiles configuration permissions. The following user permissions are available:

View: Provides view-only user access to the Routing profiles resources available in the Amazon Connect instance
Edit: Gives the user access to modify existing Routing profiles resources
Create: Gives the user access to create new Routing profiles resources
By using advanced options and selecting the Tag-based access control setting, administrators can restrict access only to routing profiles with associated tags. For example, a routing strategy designer can group a set of routing profiles for sales-specific workloads by associating a sales department tag. Tags are key-value pairs, and in this example, the tag has the key department and the value sales. Associating this tag with routing profiles related to sales workloads, the advanced security profile restricts user access to routing profile resources tagged with department:sales.

Delete: Provides users with access to delete Quick connects resources

Summary
Course summary

Review the key learnings in the course summary before taking the course assessment.

Benefits
Amazon Connect routing offers unified experiences across channels. Voice, chat, tasks, and SMS get routed through the same engine and queues. This approach optimizes contact outcomes and agent usage. Routing can scale seamlessly without additional management overhead. 



Queues
Amazon Connect has two queue types: standard and agent. 



Standard queues hold contacts waiting for available agents. Administrators create standard queues based on skills, like product knowledge, or attributes, like geography. 



Agent queues are automatically generated when users are created in the system. Use agent queues to route contacts to specific agents for personalized interactions. 

Routing profiles, priorities, and delays
A routing profile groups one or more queues matching agent skills and channels. Each agent has one routing profile that determines their eligibility for the available queues and channels. Within a routing profile, you can configure queue priorities and delays. The priority settings control the order in which queues get served. The delay settings expand the eligible agent pool as contacts age in queue.

Inbound and outbound routing
For single channel routing, consider the following: 

Contacts route through flows to queues based on agent routing profiles, queue hours, and flow logic. 
Metrics, like number of contacts in the queue and the oldest wait time, can influence routing decisions. 
Agents with available capacity receive contacts based on routing profiles, priorities, and contact age.
Multi-channel routing profiles configure concurrent channel settings, like handling one voice call or three chats. Cross-channel concurrency rules determine whether agents receive additional contacts across channels while engaged. 



Outbound calls can be agent-initiated manually or programmatically routed after being dialed out.

Built-in routing strategies
In queue-based routing, contacts get routed to agents based on the agent skills configured in routing profiles. 



The proficiency routing configuration steps are as follows:

Create predefined attributes for proficiency-based routing. 
Assign attributes to agents as proficiencies. 
Set routing criteria in flows to match contacts to proficient agents. 
Dynamically adjust contact queue priority and age.
Considerations
Service quotas 

Amazon Connect has default service quota limits for routing profiles, queues, quick connects, and predefined attributes per instance. Some quotas are adjustable.



Security 

Grant permissions through security profiles following least privilege principles. Security profiles control creating, editing, and viewing routing resources like profiles, queues, and attributes. Use tag-based access control to restrict access to specific tagged resources.
