Lesson objectives

Lesson introduction

Amazon Connect is an omnichannel contact center solution that you can integrate with your existing web applications. You can use Streams to integrate the Amazon Connect agent experience into a customer relationship management (CRM) application. You can provide agents with the tools and resources they require by integrating with other Amazon Web Services (AWS) services and partner solutions or creating custom desktops. With a custom desktop, agents can get a comprehensive view of a customer and contact in a single interface without managing multiple screens and interfaces.

Streams API

A Contact Control Panel (CCP) is a web browser application that agents use to handle customer inquiries. In a CCP, agents can do the following:

Dial, consult, transfer, or conference calls
Handle or transfer chats
Handle offline tasks related to customers
By using Streams, you can customize the functionality of a CCP. You can create your own interfaces for agent applications. For example, you can integrate the CCP with internal systems, such as CRM and core banking applications. This integration helps agents effectively address customer inquiries.

Streams provides a library that enhances web applications with extended functionality. Developers can build a web client interface that consumes events such as agent state changes and completed contacts and that can handle the agent experience. The following are key components of how streams are integrated by developers and organizations.

Concepts and terminology

With Streams, developers can build a custom CCP that agents can use to interact with customer contacts. Key concepts include the following:


Context
Context provides structured data representing the current state of a contact, agent, or connection. The application uses these contexts to display relevant information or initiate specific logic based on the provided data. Developers can get context through events or by using an interface method.


Events
Events represent changes in states for different interfaces. Applications can listen to specific events to update the agent interface or integrate with other applications and systems. For instance, developers can handle a contact incoming event to display the customer information retrieved from the CRM system to the agent.


Handlers
A handler is a callback routine that is called after an event takes place. It defines the action that follows the event. Events and handlers are linked together when the application subscribes to events. For instance, an application is notified of a contact incoming event, and a related handler is called. In the handler, the developers can get the context of the event, such as the contact information, and display it in the user interface.


Interfaces
Streams provides access through multiple API interfaces. These interfaces give developers the ability to handle events associated with agents and contacts. For instance, a web application can be notified for contact incoming events or when agent states change. API interfaces also provide action methods that can be called to get or set the context on agents, contacts, and connections. For instance, a developer can programmatically set the state of the agent. This gives developers the ability to build an integrated CCP.


Streams
The Streams API provides a real-time communication toolkit that empowers developers to integrate web applications with Amazon Connect. This bi-directional pipeline streams contact and agent events in real time. Developers can use Streams to do the following:

Display contact information
Control the agent state
Manage calls, chats, and tasks

Commonly used Streams APIs

Streams provides access to multiple APIs, including Agent, Connection, Contact, and Core. Some APIs, such as Agent and Contact, provide both event subscriptions and methods to control the various instantiated objects available in your code. For example, the Agent API provides event subscription methods and action methods that can be called on behalf of the agent. Expand the following categories to learn more about the commonly used APIs and to discover examples of events and methods for each.


Agent API
The Agent API offers methods to subscribe to events and perform actions on behalf of an agent. After initializing Streams, developers can create subscriptions and handlers for agent events, which gives them the ability to be notified when the agent's state changes.



The following are examples of agent events:

agent.onRoutable() subscribes to the routable event, which is triggered when the agent becomes available to receive new contacts. This event occurs when the agent chooses the Available button in the CCP interface. Routable states can be specific to the client or organization. For more information, see Add Custom Agent Status(opens in a new tab) in Amazon Connect.
agent.onNotRoutable() subscribes to the not routable event, which is triggered when the agent becomes unavailable to receive new contacts. When an agent is logged in but not accepting calls, they are said to be paused. The reasons an agent might be paused are for a break, for a meal, for training, or for supervision. The reasons might be specific to the client or organization. For more information, see Add Custom Agent Status(opens in a new tab) in Amazon Connect.
agent.onOffline() subscribes to the offline event, which is triggered when the agent goes offline. This event occurs when the agent chooses the Offline button in the CCP interface. Offline is the same as logged out, not paused.
agent.onStateChange() subscribes to the state change event, which is triggered when the agent's state changes. This event is called often and includes many states that are not relevant to this lesson. However, the agent might be in a not routable state and change to a different not routable state or reason. For example, an agent might go on break after completing a call, which changes their state reason from After Call Work to Break. By using this event, an application can check the current state to the new state and pause again if necessary. 

Connection API
The Connection API provides action methods that can be called to manipulate the state of a particular connection in a contact. The connection API has no event subscriptions. Connections are transient in nature. When a contact is complete, the connection cannot be accessed any longer. It is good practice not to persist connection or contact objects. 



The following are examples of Connection API methods:

connection.getContactId() gets the unique contactId of the contact to which this connection belongs. 
connection.getEndpoint() gets the endpoint to which this connection is connected. With this method, you can retrieve a destination point for your connection and implement custom logic based on this data.
connection.hold() and connection.resume() put a connection on hold and resume it. Depending on the number of parties on a contact, you can control the specific party being put on hold and being connected back.
connection.isActive() determines if the connection is active. This might help you implement logic such as testing if a connection is active before associating data or putting the connection on hold.

Contact API
The Contact API provides event subscription methods and action methods that can be called on behalf of a contact. After initializing Streams, developers can create subscriptions and handlers for contact events to be notified of new contact events.



The following are examples of contact events:

contact.onConnecting(handleContactConnecting) notifies when the contact is connecting. This event happens when a contact comes in, before it is accepted by an agent.
contact.onAccepted(handleContactAccepted) notifies when an agent accepts an incoming contact.
contact.onConnected(handleContactConnected) notifies when a contact is connected, indicating that the agent is connected with a customer.
contact.onEnded(handleContactEnded) notifies whenever the contact is ended either because the agent has ended the conversation, or the contact has been missed. The contact.getState() method can be used to determine the state of the contact and take appropriate action.

Core API
Streams provides a mechanism to initiate the connection to Amazon Connect. Initializing the Streams API is the mandatory first step to verify that the setup is correct and that the application can listen to events.

When Streams is initialized on a web page, it can automatically display the CCP widget. This built-in CCP serves as an integration interface between the web application and Amazon Connect. Organizations have the option to either use the integrated CCP or hide the widget and build customized agent experiences by using Streams interfaces and events.

How to subscribe to events

To subscribe to events, the first step is to initialize the Streams API. This helps you to verify that the application is set up correctly and that it can listen to events. The agent and contact interfaces give you the ability to subscribe to events by using methods that start with on*(). Such methods are provided with handlers, which run when an event occurs.

The following code snippet demonstrates how to subscribe to agent and contact events. First, it calls the connect.agent() method from the Agent API with the subscribeToAgentEvents function as a parameter. The subscribeToAgentEvents function runs when an agent logs in and sets up event handlers for agent state changes.

The following image demonstrates how to handle contact events. Streams uses the connect.contact() method from the Contact API to set up event handlers for changes in contact state.



Code
// Subscribe for Agent events
connect.agent(subscribeToAgentEvents);

function subscribeToAgentEvents(agent) {
agent.onRoutable(handleAgentRoutable);
agent.onNotRoutable(handleAgentNotRoutable);
agent.onStateChange(handleAgentStateChange);
agent.onOffline(handleAgentOffline);
}

// Subscribe for Contact events
connect.contact(subscribeToContactEvents);

function subscribeToContactEvents(contact) {
contact.onConnecting(handleContactConnecting);
contact.onAccepted(handleContactAccepted);
contact.onConnected(handleContactConnected);
contact.onEnded(handleContactEnded);
}

Lesson introduction

Integrating the CCP with third-party applications requires careful consideration of security and operational aspects to ensure reliable solutions. This lesson covers two topics: implementing secure authentication for single sign-on and using debugging and logging mechanisms for efficient troubleshooting and maintenance.

Security

Implementing SAML authentication is a best practice for enhancing security and streamlining user authentication across multiple applications and services. This best practice should be followed when implementing Amazon Connect and the CCP.

With SAML, organizations can centralize user authentication and authorization. This centralization reduces the necessity for agents to manage multiple credentials across applications, enabling single sign-on. It also gives organizations the ability to enforce multi-factor authentication (MFA) as an elevated security measure.

Agents log in through their identity provider (IdP) by opening a pop-up window or tab to start the single sign-on flow. Inside the initCCP() function, you can use the loginUrl parameter to link the configured IdP with Streams. Other optional parameters, such as loginPopup and loginOptions, handle the configuration of the pop-up window for login. For the CCP to load successfully, the SAML federation must be completed successfully, along with the CCP's initialization flow.

For more information, see the links in the Learn More lesson at the end of this course.

Debugging and logging

The Streams library includes a built-in logging utility that streamlines the process of gathering diagnostic logs. Developers can use the Streams logger library to gather logs for diagnostic purposes. Logs are written to the console log and also kept in memory. 

You can use built-in logs, which store agent actions and event timing information. Use Download CCP logs from the CCP user interface to gain access to these logs. You can then use the CCP Log Parser tool(opens in a new tab) to access the logs in a user-friendly, readable format for analysis and troubleshooting.

Another option to access logs is to programmatically use the getLog() method. You can configure the level of information this method returns by setting the log or console level. The following code image shows how to instantiate the getLog() method and set the DEBUG level for logs and the console. 



Code
const rootLogger = connect.getLog();

// Set log level.
rootLogger.setLogLevel(connect.LogLevel.DEBUG);
// Set console output level.
rootLogger.setEchoLevel(connect.LogLevel.DEBUG);

You can also request that the logs be downloaded to the agent's machine in JSON form by calling connect.getLog().download().

For more information, see the links in the Learn More lesson at the end of this course.
