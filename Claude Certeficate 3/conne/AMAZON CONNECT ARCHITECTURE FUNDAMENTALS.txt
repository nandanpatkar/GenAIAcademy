Lesson 11 of 28
Defining Routing Profiles
A routing profile is a collection of queues that an agent services contacts from. Routing profiles make it possible for agents to service multiple queues in the proper priority order.

A routing profile is like a set of rules that decides the following:

•
Which types of customer communications (voice, chat, email, task) an agent can handle

•
Which customer queues (waiting lines) the agent is connected to

•
How many conversations an agent can handle at the same time

Applying routing profiles to agents

Imagine a school cafeteria with various lunch lines such as pizzas, sandwiches, and salads. These lines represent Amazon Connect queues for different inquiries. Routing profiles work like instruction cards for cafeteria servers. They specify which lines each server can work at and in which priority order.

These cafeteria instructions mirror how Amazon Connect routing profiles direct customer contacts to qualified agents. The system helps support efficient handling while balancing workloads across the team.

Example of a real-world use case

Different routing profiles accommodate agent experience levels. Consider the following two types of agents:

•
New agents might only handle chats, and they might handle them one at a time.

•
Experienced agents might handle one voice call and up to three chats simultaneously.

You would create different routing profiles for each type to appropriately route customers while considering the experience level of the agent.

Available settings in a routing profile
When creating a routing profile, you will need to configure the following settings.


Channels
Channels are the various types of communications the agent can handle, such as the following:

Concurrency
Concurrency determines how many conversations agents can handle simultaneously. For example, agents might manage up to three chat interactions at the same time.

You can also configure whether agents can accept chat requests while actively engaging in phone calls.


Queues
Queues determine which contacts connect to specific agents.

You can set priority levels for different queues and implement delay timers that control when contacts from certain queues reach agents.

Understanding Flow Types
Flows control the customer experience in your contact center. Amazon Connect provides several types of flows, each built for different purposes. Each flow type in Amazon Connect contains only the building blocks available for that specific flow type.

Insider tip: Make sure you select the correct flow type when creating a new flow. Each flow has blocks specifically available for that flow type.


Inbound flow
These are the primary flows that handle initial customer interactions and are used when a customer initiates a call or chat.


Campaign flow
These flows are used to manage what the customer experiences during an outbound campaign.


Customer queue flow
These flows are designed to manage customer queues, such as prioritizing certain customers or routing them based on their needs.


Customer hold flow
These flows are used to manage what the customer experiences when they are on hold.

With this flow, one or more audio prompts can be played to a customer using the Loop prompts block while they wait on hold.


Customer whisper flow
This flow is used to manage what the customer experiences as part of an inbound call immediately before being joined with an agent.

The Agent whisper and Customer whisper flows are played to completion, then the agent and customer are joined.


Outbound whisper flow
This flow manages what the customer experiences as part of an outbound call before being connected with an agent.

In this flow, the whisper is played to completion to the customer, then the agent and customer are joined. For example, this flow can be used to enable call recordings for outbound calls with the Set recording and analytics behavior block. For more information, see Flow Block in Amazon Connect: Set Recording and Analytics Behavior(opens in a new tab).


Agent hold flow
This flow is used to manage what the agent experiences when on hold with a customer.

With this flow, one or more audio prompts can be played to an agent using the Loop prompts block while the customer is on hold.


Agent whisper flow
This flow is used to manage what the agent experiences as part of an inbound call immediately before being joined with a customer.

The Agent whisper and Customer whisper flows are played to completion, then the agent and customer are joined.


Transfer to agent flow
This flow is used to manage what the agent experiences when transferring to another agent.

This type of flow is used to tranfer a contact directly to an Agent bypassing waiting in a standard queue. For more information, see Flow Block in Amazon Connect: Transfer to Agent(opens in a new tab).


Transfer to queue flow
This flow is used to manage what the agent experiences when transferring to another queue. 

This type of flow transfers contacts to standard queues. A Set working queue block placed earlier in the sequence determines which specific queue receives the incoming contact. This structure ensures proper contact routing and assignment. For more information, see Flow Block in Amazon Connect: T(opens in a new tab)ransfer to Queue(opens in a new tab).

To keep up to date with the flow types available in Amazon Connect, see Choose a Flow Type(opens in a new tab) in the Create a Flow section of the Amazon Connect Administrator Guide.

Insider tip: Do not place any sensitive information in a Transfer to agent flow.

You should never include sensitive information in a Transfer to agent flow for a critical reason. During cold transfers, if the transferring agent disconnects before completion, the flow plays back to the caller instead of the receiving agent. This means any confidential information within the flow would be inadvertently exposed to the customer.

Why these metrics matter

It is important to monitor these key metrics in your contact center for the following reasons:

•
Service level: Shows if customers are being served promptly
Example: 80 percent of calls answered in 30 seconds

•
Average handle time (AHT): Indicates agent efficiency and contact complexity
Example: Average handle time: 5 minutes 23 seconds

•
Abandonment rate: High rates suggest customers are waiting too long
Example: 5 percent abandonment rate

•
Occupancy: Shows if you have the right staffing levels
Example: 85 percent occupancy

•
Contacts in queue: Indicates current demand and potential wait times
Example: 15 contacts waiting in the technical support queue

When looking at these metrics, consider them together rather than in isolation.

For example, a high abandonment rate with high average handle time might indicate agents prioritize thoroughness over efficiency. They deeply engage with each customer, causing others to wait longer and potentially abandon calls. A low abandonment with low handle time could suggest agents rush through interactions. They process customers quickly rather than solving issues completely. This reduces wait times and abandonments but might sacrifice service quality.
